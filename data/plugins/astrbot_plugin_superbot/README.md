## 初次安装

1. 在BotFather创建新的机器人，显示名称“大海传媒超级机器人”，Token仅填写AstrBot机器人后台。不要复用监控或旺商聊机器人。关闭该实例自动同步通用管理命令，避免展示其他系统命令。
2. 在可信私聊或已有可信记录核实个人账号 @example_owner 的数字UID；不得用用户名搜索结果直接授予超管。将数字UID和新平台ID填入插件配置。
3. 在插件配置的chat_provider_id、embedding_provider_id填写已有可用模型ID。首次启用自动创建独立人格、知识库、配置与新平台路由；拒绝覆盖已有其他配置路由。玩家知识库仅导入 `docs/player-help.md`、`docs/player-services.md`，按文件摘要去重；人格独立配置，维护文档不导入。没有新Token和UID时保持禁用。
4. 若Keno需加拿大出口，在插件后台填写独立代理URL。插件支持http/https/socks5，不从旧Go服务读取密码；不修改Telegram、模型或全局代理。
5. 安装随项目提供的Telegram应用重建钩子补丁。它仅支持插件重新注册回调，无插件注册时旧逻辑不变。
6. 启用插件后，超管私聊 /start。初始没有业务开放；在管理中心配置参数、授权其他管理员并逐项开启。

## 管理操作

「全部功能启停」只汇集全局开关，不修改逐群设置。「玩法管理」按“开奖型玩法／互动玩法”整理加拿大28、积分快三、双人对赌、积分转盘、老虎机PvP与扫雷接龙。逐群页面统一显示玩法中心总开关、玩法总开关、本群开关、近期业务和异常数量；开关互不覆盖。群已登记但玩法未启用时不能参与，不自动把测试群配置推广到其他群。

「玩法管理 → 本群玩法启停」新增同群总览，明确显示总开关、本群开关和实际拦截原因。一次预览确认可开启当前群的转盘、老虎机、扫雷、快三与对赌，保留既有参数，并确认本群老虎机与扫雷新版准入；单项开启也在确认页明确新版范围。配置采用群及玩法版本复核、单事务和审计，不改总开关、其他群、加拿大28倍率或钱包。旧按钮未明确新版开放时不能绕过确认；新群默认关闭，授权不自动修改开关。

管理入口现为「全部功能启停」「玩法管理」。加拿大28页面只展示倍率房、开放时间和采集／投递异常，不混入对赌数据；对赌和积分快三按群列出开关、进行中数量及待核查状态。对赌同时受玩法中心、对赌总开关、当前群启用状态及对赌群开关约束。首次升级保留已登记群原开放状态，新登记群默认关闭对应玩法，需管理员开启。逐群设置要求玩法业务权限、群管理权限与现有 Telegram 管理员校验；保存前二次确认及版本核对。关闭后只停止新业务，已锁定挑战或已受理期次仍按原快照结算。所有业务继续按 chat 隔离，不跨群共享状态。

管理私聊的通用渲染默认采用加粗标题与原生可折叠引用块，输入内容仍转义；按钮用于业务选择和确认，不解析用户提供的 HTML。积分配置以中文字段展示，广告与玩法保留各自分类页。授权及撤权边界不变。

广告管理使用概况首页：广告位设置、订单审核、投放频道、广告栏容量、广告异常、充值核查。数据以分段文本和原生折叠引用显示，按钮只负责选择和操作。已有广告位点击字段即可单项修改，核对保存；若其他管理员已修改配置，旧确认会失效。新建仍逐项填写，原有审核、核款、价格校验和历史订单快照规则不变。

- 超管“功能启停”控制入口。关闭模拟28同时暂停未来追号，已接受下注继续结算；关闭广告仍执行已有到期撤销置顶。
- “生成授权链接”：仅首位超管可操作，目标支持数字UID、@用户名、t.me/用户名；新向导授予全功能业务管理权限，但不含授权和撤权。期限1—365天，领取链接10分钟有效；接收者须确认。用户名需先私聊建立记录并核验UID。撤权仅首位超管可操作，同时作废该用户尚未领取的链接。
- “广告管理”：表单设置套餐；期限“30天”为连续30天，“月”为按生效日加一个日历月并在短月取月末。名额按目标群/频道统计，本插件不管理其他管理员的置顶。
- “审核订单”：内容通过与实际核款分别确认。用户可提交图片或流水信息；“查看凭证图片”只展示用户提交材料，不代表到账。
- “积分管理”：签到数、聊天奖励、间隔、每日上限和奖励群列表；调整积分须指定群及原因。余额、签到和聊天奖励上限按群隔离，聊天至少5个有效字符。
- “玩法管理 → 加拿大28”：管理倍率、限额和开放时间；每群使用管理员指定倍率，玩家不自行切换。采集成功不等于下注已经开启。

## 维护

数据位于 data/plugin_data/astrbot_plugin_superbot/平台ID的SHA256/superbot.sqlite3。数据库权限0600。只读状态/一致性备份工具见 `maintenance.py`。

```text
python data/plugins/astrbot_plugin_superbot/maintenance.py status /完整路径/superbot.sqlite3
python data/plugins/astrbot_plugin_superbot/maintenance.py backup /完整路径/superbot.sqlite3 --destination /新的备份路径/superbot.sqlite3
python data/plugins/astrbot_plugin_superbot/maintenance.py verify /备份路径/superbot.sqlite3
```

升级前停用插件，等待terminate完成，备份代码、插件配置、独立配置文件及一致性SQLite快照。初版schema=1；新增迁移不得覆盖历史流水。不要复制sqlite主文件替代在线备份（存在WAL）。备份也含广告与审计，应限制访问。

回滚先停止新版本，再恢复代码，保留上线后数据库。不启动第二个polling，不通过整库恢复抹掉新订单；若schema不兼容，应保持停用并使用匹配代码。新增Telegram钩子回滚会使本插件不兼容，应先停用本插件；不会要求修改其他业务插件。

开奖异常：管理员查询采集状态，检查加拿大代理与源可用性；异常详细日志仅含类型。缺失的历史订单保留pending，通过独立真实数据补采后结算。数据冲突不自动解除，须维护人员核对原始证据；禁止直接覆盖已结算数据。每次仅处理最多500笔结算，后续轮次继续。

广告发送/置顶/解置顶中断会转为review。Telegram发送没有可查询的业务幂等键，因此未知发送不自动重试。人工确认实际群状态后处理，禁止盲目复制订单重发。定时任务只对已持久保存的本插件消息ID操作；关闭或过期不删除正文。

本插件不宣称固定数据库大小：积分流水、广告和开奖证据持续增长。观察磁盘剩余量、数据库大小、待结算数量、review广告和unknown通知。按钮与表单过期记录自动清理，审计和积分流水不自动删除。清理历史需另行明确保留策略。

## 扩展

新增模块实现自己的服务，使用Store.tx处理本地事务；需要积分时调用Store.credit并提供稳定业务唯一op。跨网络操作先写执行声明，再调用上游，结果未知保留待核查。不要在数据库事务内await。

## 加拿大28群内文字玩法

群内发送 `jnd`、`加拿大` 或 `Canada` 激活本人本群30分钟文字下注，直接发 `ds300xs300bz200` 或 `dd100 27/10` 提交；按钮和旧斜杠下注入口已停用。整条原子受理，反馈引用原消息并带本人用户名，成功发送后约10秒撤回，用户原消息保留。停止开盘和封盘公告，仅有下注的期次发布合并的开奖结果及结算名单，约30秒撤回。“历史”查询最近10期开奖结果，约60秒撤回；“签到”按本群领取奖励，约10秒撤回。个人记录、规则、积分查询保留。详见 `docs/game-rules.md`；客服沿用原有流式 MarkdownV2 转换，不改变其他机器人。

维护、切换和回滚约束见 [玩法与播报维护](docs/game-rules.md)。`game_broadcast.py` 与原投递使用同一群锁，独立持久快照不修改赔率、限额或积分流水。审计、开奖和播报元数据持续增长，应监控磁盘，不自动删除安全凭据。
## 积分转盘

支持单抽、5连抽、10连抽；每档连抽按钮显示总投入，各抽独立使用原概率。每抽占一次每日额度，冷却按整批结算时间计算。单事务扣总投入、保存全部倍率和合计返还，余额或次数不足整批拒绝。`wheel_orders.draws` 增量迁移，历史订单默认1；`stake`与`payout`为整批合计，逐抽倍率保存在配置快照的`results`。回滚需使用识别该字段的兼容版本，不可恢复旧每日计数逻辑。

群菜单分为「🎮 玩法大全」与底部群专属回复键盘。玩法大全只展示加拿大28、双人对赌、积分转盘；积分、签到、历史、流水、输赢、帮助及已开放的群规、常用说明、头像、客服和帮助进入键盘。现有已发布键盘保留；已取消周期性发布键盘说明，启动、重启和配置变化不再主动发送独立键盘公告。新群不自动发布，停用群不主动发送收起公告，但所有旧按钮文字仍实时检查群与功能开关。设置 `is_persistent=False`、`one_time_keyboard=False`，通过 Telegram 输入框旁的原生键盘图标收起或展开；不再识别“菜单”“显示键盘”恢复命令。

`/wheel` 从群快捷命令列表移除；旧文字命令仍兼容。已有玩法面板的查询按钮在原有效期内保持本人本群查询，不改写历史消息。群键盘发送普通文字，继续使用原消息ID、发言人及本群权限检查，查询的原有撤回时间保持不变。

群内发送“转盘”“积分转盘”或 `/wheel`，也可从玩法中心打开。GIF动画面板绑定本人和当前群，10分钟过期；点击档位立即抽取，倍率包含本金。默认50／100／500／1000积分，每人每群每天20次、间隔3秒，北京时间零点重置。结果更新原面板；消息更新失败可刷新查看，不重复扣分或重抽。

新桌规则 `slots-5`：发起者选定金额，全桌须同额加入，后台拒绝不同金额按钮。多人先比三连＞对子＞散牌，同牌型再比独立随机幸运点（1—1,000,000，高者胜），唯一胜者获总池90%，抽水10%。最高牌型和点数均相同才免费加赛，最多追加5轮仍平局全桌退款。单人散牌0倍、对子1倍、三连6.2倍，含本金不另抽水。每轮水果与幸运点先保存再派发，重启不重抽；GIF说明及汇总展示点数。动画投递结束后至少等8秒，再独立发送结果，不修改原报名面板为结果；通知成功60秒后清理本桌已知消息。旧 `slots-1/2/3/4` 桌次继续按旧快照完成；下段原面板更新方式仅适用于 `slots-3`。

「全部功能启停」增加总开关，同时受玩法总开关约束；「玩法管理 →老虎机PvP」提供逐群启停、近期桌次、托管及投递异常。默认关闭；首轮仅开放“机器人测试”超级群。关闭取消未锁定桌并退款，已锁定的保存结果继续结算。冻结结果与派发分两阶段：结果先持久保存，派发在独立事务内原子完成，失败不重新抽取。

## 加拿大28与积分快三房间路由
加拿大28和积分快三使用“用户＋群”互斥会话。玩法大全按钮与 `jnd/加拿大/Canada`、`快三/k3` 文本入口效果一致，激活30分钟且下注不续期；`取消/退出`退出当前房间。进入哪个房间，所有疑似下注文本只交给该玩法解析，禁止失败后回落到另一解析器。未进入房间时只对明确下注格式给出选择提示，普通聊天不入库、不核验成员。

两套解析器共享中文和常用拼音缩写。加拿大28数字范围为0—27，并支持球位、边路和数字对格式；快三数字斜杠表示和值3—18，越界的完整数字项可跳过，大小单双组合使用三骰真实概率对应的固定返还倍率。两者均以原消息ID幂等、按群钱包原子扣分，切换、退出、超时和迟到消息不会撤销或跨玩法转投。快三三颗原生骰子严格串行，未知发送进入待核查而不重掷；结算公共面板用可点击用户提及及原生折叠块展示排名、投入、返还和净输赢。

### 加拿大28采集与延迟核查

采集与结算使用独立异步任务，慢采集不阻塞已有结果的结算。平时10秒轮询，在上期时间＋210秒前10秒至后90秒的有限窗口内改为3秒；请求耗时计入间隔。沿用长连接，完整请求最多15秒，网络异常按10／20／40／80／120秒退避，限流遵守服务端等待时间；实时采集和历史补采共用请求锁与退避。

`draws.received`仍表示最后验证时间，**不能当作首次入库时间**。新增`draw_timing`记录首次发现、最后验证与结算时间；旧记录首次发现为未知，不反推。`keno_poll_runs`记录请求与入库处理耗时，最多5000条、最长7天；`gt_delivery_timing`记录结果入队和发送成功时间，保留30天。历史补采及启动追赶单独标记，不能计作正常实时延迟。

源时间到首次发现包含上游发布时间差与本地轮询等待，不等于纯网络耗时；优化轮询不能保证上游提前出结果。回滚只恢复兼容代码并重载插件，保留新增诊断表及业务流水，不重抽、不重放结算。
