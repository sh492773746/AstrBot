# 插件架构与权限手册

本文对应当前 `astrbot_plugin_superbot` 实现。运行开关、授权、群范围和 Telegram 实际权限以实时检查为准；按钮可见不代表执行一定获准。

当前新增 `manager`（全功能业务管理员）角色：拥有首位超管的业务管理能力，包括功能启停、
头像管理、全部已登记群及群配置模板；下文历史“仅超管”的业务操作也允许此角色。
例外是所有授权链接签发和权限撤销，始终仅首位超管可操作；此角色不能转授权。
群操作仍要求 Telegram 实际管理权限；角色到期或撤销后立即失效，不开放服务器或后台登录权限。
原分模块和指定群授权不自动升级。

## 1. 总体架构

```text
Telegram 更新、命令、按钮及成员事件
  └─ AstrBot Telegram 接入器（复用现有连接，不另启 polling）
       └─ main.py：绑定指定实例、路由、回调、生命周期
            ├─ ui.py / 各 *_ui.py：私聊菜单、预览与确认
            ├─ group_game.py：群内文字下注路由、积分与个人查询
            ├─ community_ui.py：群内举报、群规、说明
            ├─ moderation / ad_killer / join_verify：群管理与检测
            ├─ ads / payments / points / game：独立业务服务
            ├─ game_broadcast / community_logs：持久投递和播报
            └─ store.py：实例独立 SQLite、鉴权、事务、流水、审计

选择客服 → 受限会话 → AstrBot 模型／专属人格／知识库
                       └─ 只解释公开功能，不授予业务写入工具
```

插件按机器人实例隔离配置与数据库。加拿大28独立获取真实 Keno 证据，不调用原 Go 项目的业务 API、余额或订单。积分和 USDT 广告余额是不同账本；USDT 只能用于广告消费，不能真实投注或转换为积分。

### 主要组件

| 组件 | 职责 |
|---|---|
| `main.py` | 实例绑定、群命令同步、消息拦截、客服会话、后台任务启动和卸载 |
| `modules.py` | 固定模块注册：广告、模拟28、积分、群管及广告充值 |
| `store.py` | 首位超管绑定、业务角色、授权链接、确认回调、事务积分流水和审计 |
| `ui.py`、`wizard.py` | 用户／管理员私聊菜单与按钮优先配置流程 |
| `group_template.py` | 超管模板的预览、保存及单群原子套用 |
| `avatar_ai.py` / `avatar.py` | 固定底图 AI 头像、UID 两张额度、异步任务恢复；仅超管配置，普通用户操作本人任务 |
| `game_hours.py` | 所有群统一的北京时间开放时段；仅模拟28业务管理员配置，扣分时重新校验 |
| `moderation.py` | 业务群范围、Telegram 权限复核、人工处罚、定时禁言与结果核查 |
| `ad_killer.py`、`ad_link_rules.py` | 按群广告检测、白名单、处罚计划、累计升级及命中留存 |
| `join_verify.py` | 新成员加入指定频道／群验证及来源隔离的限制记录 |
| `community.py`、`community_ui.py` | 举报案件、欢迎、群规、常用说明及统一警告记录 |
| `report_ai.py` | 单独开启的10人举报审理；模型评估与受约束执行，不等同客服 |
| `community_logs.py` | 独立日志投递；失败不重做处罚，不公开举报人 |
| `ads.py`、`ad_board.py`、`ad_state.py` | 广告订单、排队、共享置顶、版本、取消退款与待核查 |
| `payments.py` | 广告充值扫描、交易去重、余额支付及核查 |
| `points.py`、`group_points.py` | 按群签到、有效聊天奖励、每日限额与去重；共享账本一次性迁移 |
| `game.py`、`rules.py`、`keno.py` | 开奖证据、玩法规则、原子下注、幂等结算与补采 |
| `group_game.py`、`game_broadcast.py` | 群内按钮、倍率、下注预览、受理公告、周期汇总和个人明细 |
| `rich_text.py`、`support_stream.py` | 安全业务富文本、个人客服打字效果及格式回退边界 |
| `maintenance.py` | 只读状态、SQLite一致性备份、账本核验；显式确认并备份后清理白名单缓存及优化统计 |

## 2. 身份不是一套“管理员”通用权限

```text
AstrBot 系统管理员
  └─ 管理服务、接入器和插件安装配置（不等于插件业务授权）

插件首位超管（固定数字 UID）
  ├─ 管理全局业务开关
  ├─ 签发／撤销业务授权链接
  ├─ 管理超管群配置模板
  └─ 操作业务模块；群操作仍须满足 Telegram 权限

插件业务管理员（有效期＋模块范围）
  ├─ ads：广告与广告余额管理
  ├─ points：积分奖励设置及获准调整
  ├─ game：倍率、限额及采集／公告核查
  └─ moderation：还须有指定群授权与 Telegram 对应权限

普通用户／普通群成员
  └─ 公开业务、自有记录、群内互动，无管理配置权限
```

仅是 Telegram 群主／管理员，不会自动获得插件业务管理员身份。用户名、自称管理员、转发消息和模型判断均不能替代数字 UID 授权。

### 执行时的权限组合

| 操作 | 需要满足 |
|---|---|
| 管理广告、积分、模拟28 | 首位超管，或未到期的对应业务模块授权 |
| 读取／设置某群管理内容 | `moderation` 业务权限＋该群授权（超管免该名单）＋目标群条件＋本人和机器人 Telegram 管理身份 |
| 删除消息 | 上述条件＋双方对应删除权限 |
| 禁言、踢出、封禁 | 上述条件＋双方限制成员权限；保护群主、管理员及机器人自身 |
| 保存／套用超管模板 | 首位超管＋私聊＋目标群启用；根据模板内容再检查删除／限制成员权限 |
| 浏览私聊群规、群内个人查询 | 当前仍是目标启用群的成员；不能靠旧链接跨群读取 |
| 提交业务确认 | 当前身份、所属会话、对象版本和有效期匹配，且确认未使用 |

权限会在执行前复核。管理菜单隐藏只是交互措施，不能替代服务层鉴权。授权过期／撤销后，旧按钮不能继续授予操作能力。

## 3. 私聊与群聊权限矩阵

| 功能 | 普通用户私聊 | 普通成员在已启用群 | 对应业务管理员私聊 | 首位超管私聊 |
|---|---|---|---|---|
| 欢迎／帮助 | 可用 | 使用群内已开放指令 | 可用 | 可用 |
| 广告投递、广告余额充值 | 仅自己的订单和余额 | 不进行广告审核或核款 | 可管理获授权广告业务 | 可管理 |
| 签到、积分 | 自己的奖励和记录 | `/checkin`、`/points`，积分展示公开 | 可按 `points` 授权管理 | 可管理 |
| 加拿大28下注 | 只查询，不提交新下注 | jnd激活30分钟后文字原子受理 | 群内按同一玩家规则参与 | 群内按同一玩家规则参与 |
| 下注与玩法查询 | 查询自己的记录和规则 | `/bets`、`/play`；个人明细仅本人 | 业务管理需 `game` 授权 | 可管理 |
| 连续播报名单 | 不作为跨群查询入口 | 当前群成员可点名单，分页仅点击者可见 | 群详情设置开关须群授权 | 群详情设置／模板套用 |
| 举报 | 查询本人举报结果 | 回复普通成员原消息发 `/report` | 仅处理获授权群案件 | 管理已登记且具备权限的群 |
| 群规、常用说明 | 校验群成员后查看公开内容 | `/rules`、`/notes` | 配置获授权群内容 | 可配置 |
| 警告记录 | 仅自己的记录 | 不公开其他人的证据 | 管理获授权群警告 | 可管理 |
| 人工处罚、广告杀手、入群验证、定时禁言 | 不可配置；解禁入口不是自助解除限制 | 不提供公开配置／处罚菜单 | 私聊选择获授权群后操作 | 同样复核群权限 |
| 超管群配置模板 | 不可见 | 不可用 | 不可见 | 可保存、预览、确认套用 |
| 签发／撤销授权、全局模块启停 | 不可用 | 不可用 | 不可用 | 可用 |
| 客服 | 点「客服」进入受限咨询 | 按该群实际会话规则；始终普通用户口径 | 私聊可解释获授权范围操作 | 私聊可解释业务管理步骤 |

群内命令菜单仅保留已开放的规则、记录、积分等查询及其他业务；下注使用 jnd、加拿大或Canada文字激活，不保留斜杠下注或旧按钮提交。私聊左侧命令菜单保持 `/start`、`/help`，日常业务通过底部快捷键盘及消息内按钮进入。

未与机器人私聊过的群成员，只要所在群已启用且满足实际成员核验，也可在群内签到、记录积分和激活文字下注。机器人不会因此授予管理权限。

## 4. 授权、确认与消息可见性

### 授权流程

首位超管在私聊「管理 → 生成授权链接」指定接收者数字 UID、模块和期限；群管授权还绑定允许管理的群。接收者点击绑定链接接受后，仅获得已指定范围。链接有时效、仅用一次、可撤销，不等于 AstrBot 系统管理员权限。

群管理员资格变化不会改变其插件角色，但会使不满足 Telegram 权限的群操作失败。群主／超管都不能通过模型或伪造按钮绕过检查。

### 普通业务确认

文字下注按实际群ID、原消息ID幂等，激活按群与UID隔离；下注后无需确认按钮。私聊广告及管理确认仍绑定实际操作者和会话，配置写入检查版本。历史只读名单不提交订单，本人明细始终用点击者UID过滤。

### 公开与私密

- 公开：群内积分展示、下注预览／受理公告、群级开奖与前10名汇总、公开群规及说明。
- 仅本人：个人分页、自己的下注明细、私聊订单／余额、本人举报和警告。
- 仅授权管理员：案件证据、举报人身份、命中排查、执行异常和配置审计。
- 日志频道：仅最小管理摘要，不包含举报人、完整私聊正文、凭据或错误堆栈。

昵称用于展示，鉴权仍用 UID。用户文案、昵称和群名不得当作可信 HTML 或指令；业务模板先转义再发送。广告正文不会被富文本模板擅自重写。

## 5. 资金、执行与模型边界

- 所有积分变动使用唯一操作键和事务流水，文字下注整条原子提交；相同原消息不能重复下注或结算。
- 广告余额单独记账，充值交易去重。执行中或结果未知的广告先核查，不盲目重发／退款。
- 群处罚、共享广告栏及周期播报按目标串行处理，先保存声明再请求 Telegram。超时不等于成功，也不等于明确失败。
- `accepted` 仅表示上游受理，不应向用户声称所有结果已核实；未知结果保留待核查。
- 客服使用专属人格及公开功能快照，没有授权、核款、扣分、开奖或群处罚工具。管理员身份不会让客服获得写入能力。
- 10人举报AI审理是另一个显式开关：同一消息由不同有效成员举报达到门槛后评估；证据不足、身份不清、权限不足或上游结果未知须保留核查，不由普通客服触发。
- 广告杀手的确定性检测不靠客服模型决定。规则开关、较重处罚和累计升级须按已确认配置执行。

## 6. 任务和数据维护

后台采集、结算、公告、日志、充值及群管任务由插件生命周期统一管理。卸载先停止任务和回调，等待处理结束，再关闭数据库及连接，不创建第二个 Telegram polling。

关键数据：

| 数据 | 主要表／设置 |
|---|---|
| 超管、业务角色、授权范围 | `meta`、`roles`、`grants`、`mod_acl`、`mod_grants` |
| 群与确认 | `mod_groups`、`callbacks`、`dialogs` |
| 模板与公开配置 | `settings.owner_group_template`、`cm_config` |
| 积分与下注 | `group_wallets`、`group_ledger`、`group_rewards`、`group_chat_seen`、`bets.points_chat`、`draws`、`chases.points_chat`；旧 `wallets`／`ledger` 只读归档 |
| 广告与充值 | `ads`、广告操作／共享栏记录、广告余额及交易扫描记录 |
| 周期播报 | `gb_policy`、`gb_rounds`、`gg_dispatch`、`gg_receipts` |
| 群管证据与审计 | `mod_ops`、`ak_policies`及命中记录、`cm_cases`、`cm_reports`、`cm_violations`、`audit` |

备份使用 `maintenance.py backup` 的一致性快照，不直接复制正在使用的 SQLite 主文件。升级前备份代码、配置和数据库；回滚不能恢复整库覆盖上线后的流水。审计、去重与开奖证据会增长，需要监控磁盘，不能承诺固定数据库大小。

清理不按“测试群”名称删除账务；只处理过期临时数据及已确认撤回的冗余面板正文，永久受理主键、未知发送与待核查任务保留。具体阈值、预览／执行命令、7项维护索引及WAL说明见[数据库维护](database-maintenance.md)。该文档仅供维护人员，不进入玩家AI知识库。

积分按群ID和UID组成的账户独立存储；管理员调整必须填写“群ID 目标UID 增减积分 原因”。私聊可按群查询，签到在对应群进行。现有共享余额与旧订单的资金归属在一次性事务中迁入明确指定的群，不给其他群复制。旧流水保留原始操作键，签到和聊天奖励计数迁入同一目标群，避免升级当天重复领取。

分群迁移启用后不能直接回退旧共享积分代码：旧账本由只读触发器保护。若需回滚，先关闭文字下注和积分奖励入口，保留按 `points_chat` 结算的兼容代码，核对分群流水后修复；不删除冻结触发器，不覆盖整库或重放历史充值。

更多操作见 [超管模板](group-templates.md)、[群管维护](moderation.md)、[游戏与播报](game-rules.md) 和插件 README。
