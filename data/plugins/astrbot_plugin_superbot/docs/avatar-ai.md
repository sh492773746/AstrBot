# 专属头像：AI 固定底图设计

本说明取代旧版 `avatar.md` 中“本地固定合成、不调用 API”的生产流程。

## 使用

私聊「我的 → 专属头像」，或已启用管理群内 `/avatar`。显示名以“大海传媒”开头，
可选择自动提取的昵称或自行填写1～8个汉字、英文字母、数字。
自填时回复机器人指定提示；其他聊天不会被当作名字。
仅已登记且启用群的当前成员可以新增制作。私聊先根据已知群身份定位，
再实时核验成员资格；未被机器人识别过的成员请先在所属群发送 `/avatar`。
不遍历全部群查找陌生人。确认时和真正提交付费接口前都核验；核验暂不可用则不提交。

先展示已验收的风格样例，再确认昵称与制作规则；此阶段不调用付费接口。
确认后才使用 `gpt-image-2.5` 编辑固定底图。龙纹、品牌与书法由固定提示词约束，
不接受用户上传底图或自由绘图提示。AI 可能微调原图细节，不能保证像素完全不变。
新增昵称相对风格参考图下移约画面高度的4%，水平居中，保留底部金边间距；
品牌文字不移动。此规则用于新确认的制作，不自动重做历史成品。

每个数字 UID 累计两张，私聊和所有群共用；改名不重置。
制作中预占一次，文件可靠保存后成为成功额度；明确失败释放额度。
超时且没有任务 ID 的请求保留待核查，不能当作失败释放后再次收费。
成品发回提交的会话；群内成品公开可见。文件已保存但发送失败时，可再次领取同一文件，
不重新生成、不再次扣次。再次领取表示用户明确请求副本。

群内样例、菜单、自填提示和制作进度仅向发起者展示；成品以公开图片发送，
便于全群直接查看。私聊成品保留 PNG 文件形式。
确认后的进度每五秒尝试更新，显示排队、提交、绘制和已等待时间，不提供虚假完成倒计时。
进度通过独立后台任务更新，限流按服务端要求退避；消息失效后停止更新，
不会退化为群内公开进度。可重新进入头像首页查询或领取，制作任务不受影响。
`avatar_progress` 保存进度消息标识，重启继续编辑已知消息，不重发进度或重新付费提交。

`/cancel` 只退出填写，不能撤回已经确认或上游已受理的任务。
查看进度或切换其他菜单不会取消制作。昵称校验与额度约束对管理员同样适用。

## 管理与权限

- 只绑定“大海传媒超级机器人”实例；超管通过「管理 → 专属头像管理」启停、分页查看记录。
- 业务管理员不能控制头像开关。用户只能操作自己的按钮、任务和成品。
- 群内新增制作要求群管理模块及该群均启用；排队提交前再次检查。
- 停用后不再提交未启动的任务；已提交任务继续核查和保存，不伪装撤销。
- 群停用后不自动向该群投递，可在个人头像入口领取已完成文件。
- 默认安装仍关闭，此次经用户要求为既有专属实例开启测试。不修改其他实例配置。
- 不给客服模型开放生图工具，也不允许模型修改用户额度。

## 接口与持久任务

密钥仅读取服务器受保护文件 `/root/.config/api-credentials/savnx-image.env`；
调用固定 `https://www.sevnx.lol/v1/images/edits/async`，模型固定 `gpt-image-2.5`。
复用已验证的底图＋参考图 multipart 请求，不将密钥写入插件配置、按钮或日志。
`avatar.py` 的本地合成保留为旧兼容与隔离样张工具，不再用于线上正式制作。

`avatar_jobs` 保存配额与成品事实；增量表 `avatar_ai` 保存任务阶段、上游 ID、
密钥指纹（不是密钥）、下次轮询和脱敏错误：

```text
queued → submitting → processing → done
                    ↘ unknown（禁止重交）
明确失败 → failed（释放额度）
```

全实例最多十个排队／处理中的任务，每用户最多一个未解决任务。单独后台任务推进，
不阻塞 Telegram 消息接收。每次提交先持久声明；进程中断的 submitting 恢复为 unknown。
插件配置 `avatar_daily_budget` 默认10、`avatar_total_budget` 默认100，按任务数限制全实例预算，
不是服务商金额报价。0停止新制作。每日按北京时间零点划分；延迟到次日提交的排队任务
须先占用次日预算。`avatar_paid_budget` 与确认事务一起预占并持久保存，历史AI任务也计入累计。
失败、待核查和已取消的预占不自动释放预算，避免重复失败造成无界费用；个人两张额度仍按原规则计算。
调低预算会暂停未提交的排队任务，已获上游任务ID的任务继续轮询、保存和投递，不重新收费。
管理页显示当日及累计使用量；调整上限需人工在插件配置操作，删除历史业务记录不能释放预算。
成品投递另设独立循环，每三秒检查已保存的待发送成品，不等待提交或轮询请求；
与手动领取共用事务发送状态，正在发送的文件不能并发再次领取。
processing 重启只查询原任务，按 Retry-After 等待，不重新提交。
密钥变化时暂停原任务查询，必须恢复原密钥；任务归属不通过换密钥绕过。
失败任务不会自动付费重试。

仅允许同源 HTTPS 图片地址，不携带鉴权下载、不跟随重定向；限制图片字节数、
格式及尺寸。下载失败可以重新读取原任务、原图片，不能生成替代任务。
成品以内部随机 ID 保存到实例 `avatars` 目录，临时文件同步后原子更名，
成功状态和配额在事务中更新。崩溃后有可靠成品则恢复，不重复扣次。
原请求未拿到 ID 的未知结果需维护人员在服务商核查。

## 维护、测试与回滚

- 监控 `avatar_ai.stage='unknown'`、错误字段、排队时间及磁盘空间，不展示上游原始错误给用户。
- 未拿到任务 ID 的提交不得盲目重发。核实服务商没有受理后，才可人工审计并释放额度。
- 备份插件、字体和模板资源、专属配置、一致性 SQLite 快照及 `avatars` 成品目录。
- AI 资源：`base.png` 固定底图、`reference.png` 融合参考、`ai-example.png` 已生成示例。
  模板版本由底图、参考图、提示词、模型和输出参数共同计算，变更后旧确认失效。
- 旧成功头像、额度及发送记录保留；不会为升级批量重新生成图片。
- 不恢复整库覆盖上线后的配额和任务，不自动删除历史审计或成品。
- 回滚前关闭入口，处理完或隔离所有 queued/submitting/processing/unknown 任务。
  有未解决 AI 任务时，禁止直接启动旧固定合成版本：旧版不能安全识别其预占额度。
- 测试使用模拟 HTTP，不额外真实生图；覆盖未知提交、原任务恢复、跨用户按钮、
  密钥变更、非法下载地址、失败释放、磁盘恢复及发送结果未知。

## 私聊资源防护

所有私聊文字和按钮共用接入限流：每人60秒内最多30次，最短间隔0.5秒，
全实例60秒内最多120次。超限在数据库写入、菜单渲染和客服模型调用前丢弃，不排队补执行。
限流提示也有统一冷却，重复点击不连续生成提示。群下注链路不受此私聊限流影响。
该限制不代替客服模型服务商的费用预算；陌生人不会因自称管理员而获得权限或工具。
