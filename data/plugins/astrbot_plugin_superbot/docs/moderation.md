## 成员选择

禁言、解禁、踢出、封禁、解除封禁统一使用分页成员按钮，每页8人，支持上一页、下一页和返回上一层。限时禁言先选成员，再选10分钟、1小时、1天、7天或输入自定义分钟数，最后预览确认。

成员页也接受 @用户名、t.me/用户名或 https://t.me/用户名。机器人只能根据已识别成员查找，并实时核对该 UID 当前用户名；未知或已变更的用户名不会直接执行处罚。成员来自机器人收到的群消息、新成员通知及回复消息，不等于全群名单；Bot API不能枚举所有普通成员。此前保存过发送者 UID 的消息也会补入候选列表，翻页时补全可查询的昵称。所有选择在最终执行前仍检查权限和目标状态。

提供人工禁言、解禁、踢出、封禁、解除封禁、删消息、每日全群禁言，以及另行启用的广告杀手。广告杀手新增规则对所有群默认关闭，群被发现或启用群管都不会自动开启广告杀手。

超管私聊发送 /start，在“管理 → 功能启停”打开群管，再进入“群管理 → 添加群”。输入数字群 ID 或公开群链接，确认登记后仍需进入该群点击“启用此群”。只支持机器人已加入的超级群，不自动入群。添加、启用及处罚都要求操作者本人是该群管理员；超管也不例外。

查看记录、编辑欢迎和说明只要求业务群管授权、该群范围及双方 Telegram 管理员身份，不强求限制成员权限。实际禁言、踢出等操作要求双方限制成员权限，删消息要求双方删除消息权限。“授权指定群”接受“目标UID 有效天数 群ID,群ID”，只首位超管可发链接。领取人必须同时拥有对应群的 Telegram 权限。链接十分钟有效且单次使用；领取会替换已有业务权限，请提前核对。撤销权限使用管理中心原有撤权功能。

选群后选择操作，通过分页成员按钮指定目标，再选择期限，范围一分钟至365天。永久禁言单独选择。预览目标后点击确认，十分钟有效。群主、管理员和机器人自身受保护。不能覆盖已有个人限制，只解除本插件可追溯且未被外部更改的处罚。

踢出表示移出后可重新加入；封禁表示不可自行重新加入。Telegram 封禁或踢出可能删除成员历史消息，操作前认真核对。删除消息使用所选群的消息链接；仅支持启用群管后机器人确实接收到、能够核验发送者的普通成员消息，不支持匿名或频道身份消息。Telegram 自身的消息删除期限仍适用。

全群禁言保存原发送权限，恢复时只恢复被本插件修改的字段。检测到权限冲突会拒绝恢复。外部管理员若把权限修改为相同值，机器人无法辨别其意图；临时接管前先暂停定时。

每群一个每日时段，例如“23:00 08:00”，固定北京时间、支持跨午夜。设置或恢复须确认，从下一个未来边界执行，不立即改群状态。若第一个边界是解禁但没有本插件的禁言记录，将暂停待核查，不替别人解除限制。暂停或删除不自动解禁，删除保留审计但不可直接恢复，需重新设置。手动全群禁言或恢复会先暂停定时。

上游受理不等于已核实完成。网络超时、请求结果未知或踢出部分成功标记待核查，该群停止提交新处罚。不要反复点击、自动重试或让聊天模型执行。群详情显示最近操作与定时故障；未知结果需维护人员核对 Telegram 当前状态和审计后处理，不提供一键忽略。

聊天模型只解释功能，不拥有处罚工具。普通用户看不到管理按钮，复制管理文字也不会取得权限。

2026-09-23 用现有 Telethon 账号只读抽样：目标群近期可见文字仅12条，另三个公开群各取70条作误判对照；“代理”“私聊”“联系”等单词同时见于正常公告与推广，不能单独作为自动处罚依据。当前目标群仅预置待评估的组合词，不开启关键词检测或其他处罚；请在私聊界面逐项确认规则与白名单后再开启。历史样本不代表未来消息，不得声称已验证零误判。

### 群链接、外部平台链接及频道转发

三个新增检测项均为独立开关，迁移时默认关闭、默认仅撤回，既有处罚和关键词不变。各项可能同时命中，同一消息仍只执行一次既定处罚。

- 「其他群／频道链接」：处理 Telegram 邀请链接、其他群的 `t.me/c` 消息链接，以及经 Bot API 核实为群或频道的公开用户名链接。支持 `t.me`、`telegram.me`、`telegram.dog`、用户名子域名和 `tg://join`、`tg://resolve`。本群已知用户名和数字 ID 放行；不凭用户名猜测群类型，无法查询的公开目标不会仅因该项被处罚。单条最多解析3个公开目标，正向结果缓存5分钟、失败30秒；短链接和网页跳转不主动访问。
- 「外部平台链接」：处理非 Telegram 域名链接，包括正文、媒体说明和隐藏链接。普通网站也可能命中，不代表已判定诈骗；请先配置官方域名白名单。原「外链」仍是更广泛的链接检测，开启后也可能命中 Telegram 链接。
- 「频道转发」：使用 Telegram 的 `forward_origin.type=channel`，处理普通成员手动转发、包括没有正文的媒体转发。普通用户转发不因此命中；关联频道自动同步、匿名频道身份保留安全跳过。复制文字或隐藏来源的转发无法可靠判断原频道，不承诺识别。

「关键词、白名单 → 群频道白名单」接受 `@username`、负数群/频道 ID，以及完整 `https://t.me/+AbCd...` 或 `https://t.me/joinchat/AbCd...` 邀请链接，多个用英文逗号分隔。邀请哈希区分大小写。白名单仅豁免对应 Telegram 链接和转发来源，不豁免关键词、联系方式、重复或刷屏。Bot API 通常无法由邀请哈希核实目标，本群未识别的邀请链接也可能命中，启用前请加入完整邀请链接白名单。不要用 `t.me` 域名白名单代替精确群白名单，否则所有该域名链接都会放行。

实现参考开源 tgbot 的分群链接锁/转发锁思路（https://github.com/PaulSonOfLars/tgbot/blob/master/tg_bot/modules/locks.py），以及 python-telegram-bot 的 MessageOriginChannel 结构（https://github.com/python-telegram-bot/python-telegram-bot/blob/master/src/telegram/_messageorigin.py）。没有引入第二个机器人框架或复制旧版 Telegram API 调用。

重复内容按同一用户标准化后至少12字的内容计数，首256字一致或相似度达到88%，默认10分钟第3条命中；最多检查该用户最近200条消息，刷屏默认30秒第6条命中。可用按钮或单独发送整数调节次数、时段及禁言分钟数。关键词为文字组合，输入 `招生+私聊,外部+群` 表示任意一组全部出现；不执行正则表达式或 AI 自主判罚。用户白名单填写数字 UID，域名白名单填写不带协议的域名（同时豁免该域名子域名）。联系方式包含常见手机号、微信/QQ 标记和邮箱。仅对文字、媒体说明和编辑内容做检测，不解析图片、语音或文件内部内容。群主、管理员、机器人自身自动豁免；转发管理员内容不豁免。

检测必须先于聊天积分及群客服回复；命中后不会计分或触发模型。每群共用群管执行锁，先保存唯一的消息命中记录再操作 Telegram；同一消息的重复事件和编辑不能再次处罚。禁言不覆盖已经受限的成员。操作超时、权限失败、进程中断或踢出部分成功会将该群广告杀手暂停。管理员通过「命中记录」查看操作步骤和待核查原因，核实 Telegram 当前状态并手动处理必要后果后，在「故障核查」二次确认；确认仅清除本模块故障、保持规则关闭，不重发也不自动恢复群管其他未知操作。恢复规则必须重新预览、确认启用。群管模块或群停用时广告杀手也停用，再启用群管不自动恢复。

命中记录仅授权该群管理员可见，包含消息链接、操作者 UID、命中规则、原文和逐步状态；可标记误判（影响后续累计统计），不能恢复已删除的消息或自动解除处罚。终态命中正文30天后分批清理；未完成或待核查的原文保留供核查；去重事实和审计元数据保留并持续增长。聊天模型不得设置规则或调用处罚接口。

## 入群后验证（需逐群启用）

在「我的群 → 当前群 → 群管 → 入群验证」可选择“仅点击按钮验证”（无其他群要求），或设置1至3个公开频道／超级群作为必加目标。机器人必须在每个指定目标中担任管理员，才能检查成员身份；当前不自动加入私密目标，也不凭邀请链接猜测目标。新成员进入已启用的管理群后，会先被本插件限制发言，收到验证按钮；有目标时须加入全部目标，无目标时直接点击放行。验证成功后仅解除本插件创建的验证限制。设置目标时，公开用户名不存在或机器人无法访问会显示具体提示；停用验证不会自动解除已存在的限制。

「广告与刷屏 → 执行开关」只管理群级自动执行总开关，规则、阈值、白名单、命中记录及样本识别均在独立的「检测规则与命中记录」页面。只有总开关及对应固定规则（外链、引流、联系方式、重复、刷屏等）均开启时，才会对该项命中的消息执行所配置的处罚。关键词、白名单和处罚阈值分别保存，不会因只打开总开关而自动启用所有规则；语义检测仅用于人工复核，不自动参与处罚。内部策略表与旧按钮回调仍沿用原有 ID，改名不迁移策略或影响已有开关。

验证记录按群、用户和入群事件去重，重启或重复更新不会重复禁言。验证失败、权限变化、网络超时和结果不明会保留为待核查，不能盲目重试。人工解除只能由该群授权管理员执行，并且会再次核对限制确实来自本功能；不会解除广告杀手、人工群管或其他外部限制。停用验证只停止新成员限制，已有验证记录仍可完成验证或人工核查。

## 群管扩展 v1.5：举报、公开内容、警告和日志

新功能全部默认关闭，不因拉群、启用群管或旧广告规则而开启。私聊「群管理 → 选群」增加五个入口，不增加底部常驻按钮：

需要快速配置时可点「套用基础配置」，预览确认后开启举报、欢迎、群规、常用说明和人工警告。模板来自插件目录 `community_defaults.json`；套用会复制到该群配置，之后可以逐群修改。模板文件后续修改不会覆盖已保存的群配置；再次套用会替换欢迎、群规和说明，原日志配置保留。该操作不改变广告杀手、累计自动处罚或入群验证。没有指定日志频道和验证目标时不会凭空开启。新发现的群仍须先由超管登记、启用，再选择套用。

- 举报处理：显示待处理数量，可开启举报及分页查看待处理、已结案、待核查。
- 欢迎与群规：编辑内容并预览，分别确认启用；欢迎支持 `{name}` 昵称和 `{group}` 群名，按纯文本发送，不解释用户昵称中的 HTML。
- 违规记录：新增人工警告、撤销警告、查看当前有效累计；只能查看获授权群。
- 常用说明：最多10条，标题40字、正文2500字，可附普通 HTTP/HTTPS 网址。不能设置回调、`tg://` 或机器人授权/命令深链。
- 日志设置：绑定专用私有频道。绑定、替换和启停均先预览再确认；绑定新频道时默认关闭，需要单独开启。

只有 Telegram 管理员身份而没有机器人业务授权，不会出现管理按钮，也不能通过旧按钮进入。超管仍需 Telegram 群管理员身份及执行对应动作的权限。普通用户的「帮助」只展示群公开说明，「我的」仅显示本人的举报结果和警告，不包含其他举报人或他人的证据。私聊查看群规和说明会重新检查成员身份。左侧命令菜单仍仅 `/start`、`/help`。

### 举报流程

成员在已开启举报的群中回复目标普通成员消息发送 `/report`，点击进入私聊的按钮，选择广告引流、诈骗嫌疑、骚扰刷屏或其他，可补充1000字以内说明，最后确认。入口绑定本人、原群和消息，10分钟过期；同一用户对同一消息不重复提交，多人举报同一消息合为一个案件。默认每人每群10分钟3次、北京时间自然日10次；为防滥用，入口申请也按相同上限限制。

举报不自动累计违规，也不触发处罚。管理员在私聊查看案件，选择忽略、警告、撤回、禁言10分钟、踢出或封禁，预览后确认。警告另选公开原因，不公开举报人补充说明；实际处罚复用已有群管执行链、权限复核及目标保护。多人同时处理只有一次能提交；超时或重启留有未完成请求转为待核查，不自动重发。待核查案件需维护人员对照原群当前状态及 `mod_ops` 审计，不提供盲目再次处罚。

管理员主动通知只面向已与机器人建立私聊、仍有该群有效授权及 Telegram 管理身份的人；送达失败不会丢失案件，也不代表没有举报。管理员进入「举报处理」查看待处理数；举报人进入「我的 → 我的举报」查看结果，不保证收到主动通知。

### 欢迎与入群验证

没有验证时，欢迎按原生入群事件去重发送。已启用入群验证时，将欢迎文案和群规、说明按钮合并至原有验证提示，不再另发一条欢迎。不会改变验证目标、通过条件或解除限制逻辑；验证异常时也不会补发一条看似成功的欢迎。重复事件及结果未知的欢迎不自动重发。

群内 `/rules`、`/notes` 或欢迎按钮可进入私聊查看；指令带 `@其他机器人` 时不响应。公开内容可以包含用户文字，但不会成为模型指令或管理工具调用。

### 统一违规累计

仅新上线后的人工警告和**完整执行并受理**的广告杀手命中进入统一账本，旧广告命中不回填。一个群、成员、原消息只计一次；无原消息的独立人工警告按确认编号去重。举报本身、待核查、失败、跳过的广告处罚不计有效次数。

默认窗口24小时、阈值3次。在「广告杀手 → 阈值与累计」设置窗口1至720小时、次数2至20，以及既有的累计升级开关和处罚。不开启升级时仅计数；一次新有效事件最多触发一次升级，同一次广告命中的直接处罚与累计升级合并。撤销警告、标记广告误判或修改阈值不立即处罚。自然过期、撤销和误判从有效次数排除，元数据仍保留。

人工警告新增前会显示累计规则及可能的处罚；规则改动后旧确认失效。不能覆盖已有个人限制；撤销警告不自动解禁，广告杀手、人工处罚与入群验证的限制来源保持隔离。

### 日志及隐私

保存日志配置时验证操作者为私有频道管理员，机器人有发帖权限；投递前再次核对群授权和频道权限。频道读者能看见管理摘要、必要成员编号、案件编号和已知消息链接。不会发送举报人身份、举报说明、完整命中正文、凭据、后台异常堆栈或原始审计 JSON。

日志以独立持久队列投递，失败不会重做处罚。发送前的临时故障或明确限流按退避重试；明确拒绝发送的记录为阻塞，可修复权限后按钮确认重试；超时、中断等结果未知为待核查，不提供重发按钮。频道替换后旧目的地待发消息不会继续发送。日志页面显示最近投递状态。

### 扩展数据维护与回滚

新增 `cm_config`、`cm_private`、`cm_tickets`、`cm_cases`、`cm_reports`、`cm_violations`、`cm_welcome`、`cm_delivery`、`cm_projection` 和 `cm_cursors`。增量建表和索引可重复执行；不改变历史资金、广告订单、积分或入群验证数据。`ak_policies` 增补 `escalation_hours=24` 并递增版本，使旧规则确认失效，原检测和处罚开关保持不变。

举报结案满30天后，每批最多100个案件清理原文和补充说明；未结案和待核查保留。过期入口临时证据满24小时后每批最多500条清理；案件去重、举报归属、结果和违规审计不删除。持续监控 SQLite/WAL 大小和磁盘剩余量，不承诺固定数据库大小。

部署前一致性备份，确认没有执行中处罚；热加载先停止接收、停止后台任务并等待在途操作结束，之后关闭数据库。重启后未完成请求标记待核查，不重放。回滚须先停新任务、核查未知处罚，再用兼容新增字段的旧代码；保留全部新表、新流水和审计，禁止整库恢复覆盖上线后数据。若回滚到按 `ak_hits` 旧口径计数的版本，应先暂停自动处罚并做口径兼容检查，不能直接恢复旧累计任务。

## 维护

新增 mod_groups、mod_acl、mod_grants、mod_ops、mod_restrictions、mod_schedules、mod_messages 和 ak_policies、ak_seen、ak_hits 表，兼容原数据库。原消息表仅保存群、消息编号和发送者；广告杀手命中表单独保存30天终态证据。审计和去重元数据不自动删除，需监控磁盘增长。

热加载前备份代码、插件配置与 SQLite 一致性快照。重启时执行中请求改为未知，错过的定时边界暂停，不补发。每群串行操作；停用模块或群会暂停计划，重新开启不会自动恢复旧计划。

回滚前停止新版任务，备份最新数据库，再恢复旧代码并重载；保留新增表，不整库回退。旧代码不认识 moderation 权限，回滚前撤销未领取的群管链接并移除有效角色中的 moderation 范围（保留其他范围），防止旧版菜单误认为群管用户有管理入口。已发生的 Telegram 处罚不会因代码回滚自动撤销。

参考接口：https://core.telegram.org/bots/api#restrictchatmember 、https://core.telegram.org/bots/api#setchatpermissions 。实现复用现有 python-telegram-bot，不另建轮询客户端。
