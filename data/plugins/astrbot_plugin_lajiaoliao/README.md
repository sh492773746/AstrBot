- 群内机器人互斥默认强制生效：所有本地已绑定辣椒聊账号（包括停用实例）发来的群文字、引用及图片直接 ACK，不下载媒体、不进入插件或模型管线。普通成员引用机器人仍按原规则响应；固定主动通知照常发送。私聊管理验收保留原授权边界，未改旺商聊／Telegram。
- 私聊 AI 和自动审核同样拒绝所有本地绑定机器人 UID，授权为群管也不能触发模型。私聊传输与已授权的固定命令不受此 AI 门禁影响；排队后新增绑定的账号也会在模型调用及回复前重新检查。完整测试状态见 `FULL_ACCEPTANCE.md`。
- 处理管线及事件回复边界再次核验发送者，阻止旧排队回复或运行中新增绑定继续互聊。绑定 UID 使用共享缓存，注册写入即失效，不按每条群消息扫描目录；不按昵称、手机号或引用中的用户判断机器人身份。
- 两机器人互发群 GIF／图片的维护验收只核对原生协议和互斥丢弃，不再将其记为 AstrBot 图片交接；普通成员图片转换能力保持不变。

- 新增“逐人引用开奖结果并发送 GIF”开关，默认关闭。开启后参与上限为 1～100 人；保存首次报名消息 ID，截止后冻结随机结果，逐人引用回复“您的奖品是 …”或“抱歉，您未中奖”，确认文字成功后立即发送已验证的 745 字节骰子动画，最后公布群汇总。报名时仍只确认报名，不提前开奖。
- 引用和 GIF 分开逐步落账。引用失败不发 GIF；GIF 超时不重发、不重抽。每步重新检查权限与业务版本，撤权停止后续通知。旧活动没有报名消息 ID 时明确记录证据缺失，不伪造引用；原文仍须在当前会话最近 200 条文字消息内，繁忙群较早报名可能无法引用。
- 逐人通知不适用功能回复自动撤回；机器人报名保护不变。真实展示测试不产生报名或中奖记录；真人正向报名、中奖和未中奖完整业务链仍需普通测试成员验收。

- 图片接入 JPEG/PNG 收发和 GIF 收发，20 MiB 与服务端限制取较小值，最多 4000 万像素、两个并发媒体任务。GIF 最多 120 帧、总解码像素不超过 1 亿。入站只允许核验过的官方 HTTPS 图片域名，逐次检查重定向和公网 DNS。语音、文件、视频、新增 @ 和图片引用不纳入本轮。
- 混合消息先整体检查，再按顺序逐条发送；部分成功或结果未知不当作整条成功，不自动重发。图片临时文件按账号隔离并清理。
- 自动化设置新增群作息、功能回复 20 秒撤回、单次计划抽奖、每日通知、独立邀请奖励及邀请门槛。日期时间按北京时间；保存只安排未来任务，不立即执行。
- 普通成员撤回、前三次撤回后递进禁言、精确刷屏撤回和自动名片同步已经实现，执行开关须通过对应实测才能启用。绑定机器人及管理员继续受保护。
- 官方资料响应目前缺少可靠封禁／注销字段，清理保持不可启用，绝不根据昵称、头像或缺失字段踢人。
- 完整目录确认管理员离群后撤销该群授权。修改无关业务不取消抽奖／通知；撤权或停用相应功能停止后续执行，未知结果不重试。
- 旧聊天命令“开启抽奖／立即开奖／定时通知／确认定时”不再启动动作，改为在自动化设置保存计划。旧任务保留恢复和授权校验。
- 协议握手升级为 2，Python 插件与预编译程序必须配套；旧新混装拒绝运行。固定支持本部署 AstrBot 4.28.1。
- v0.6.2 的 745 字节、64×56、6 帧 GIF 已在指定测试群单向发送，并核对对端 `102/type=gif` 和 AstrBot 图片交接；GIF 私聊及反向发送尚未验收。

两账号群聊及私聊共八次 JPEG／PNG 互发已经确认原生消息和 AstrBot 图片交接。另已观察到指定测试群真实原生 `102` GIF（360×360、107861 字节），并由群主实例真实发送一张 745 字节测试 GIF；对端原生格式及 AstrBot 图片交接确认。较大 GIF、私聊及反向发送尚未验收。保存计划后的空抽奖、每日通知、定时全员禁言及解除已经在指定测试群验收，结束后恢复开关及正常群状态。真人正向业务与成员维护仍待指定普通成员验证。

历史原生动作验收记录不代表恢复手动操作页面。当前能力及真实验收状态以 `capabilities.json` 和 `ACCEPTANCE.md` 为准。

插件页面只提供逐群管理。创建/编辑机器人页面负责账号登录、官方验证、恢复未保存会话和注销孤立授权；插件内部保留协议进程与消息转换接口。模型、权限执行、会话开关及业务功能由 AstrBot 负责。

## 使用入口

1. 在“创建机器人”选择“辣椒聊”，输入手机号和密码，点击“登录”完成内嵌官方滑块后直接保存。ID 自动生成，登录自动关联当前实例，无需手动绑定。
2. 未保存的授权在“创建机器人”选择“未完成的机器人”并恢复或注销。已有机器人占用的会话不能注销；历史孤立绑定仅能恢复到原实例 ID，不跨实例抢占。
3. 在平台配置或 `management` 页面逐群设置消息权限。只有主动启用机器人后才启动消息进程。
4. 群模式固定 `allowlist`，空列表禁止所有群；私聊单独控制。入站放行后仍受 AstrBot 原有白名单、权限和唤醒机制约束。

导入的测试机器人保持禁用。账号绑定不自动启用机器人，也不发送验证消息。

不同机器人使用独立登录草稿，不因同一 Dashboard 用户还有其他登录草稿而互相阻塞。每位用户同时最多 8 个有效草稿，15 分钟失效；这不限制已经登录的机器人数量。“取消本次登录”释放未完成授权，不注销已登录账号。

## 新账号登录

在创建机器人表单内完成手机号、密码与官方滑块验证。验证码只取得公开配置；取消或失败不会提交密码。超时后先刷新登录状态，避免重复提交。密码和滑块证明均不写入机器人配置。页面刷新后，在“未完成的机器人”选择自己的授权，点击“恢复”继续；不再提供独立插件登录页面。

## 运行与安全

- 官方平台类型保持 `lajiaoliao`，使用注册器提供的图标。创建表单调用插件的授权和绑定接口，不使用旧硬编码注册接口。插件运行包需配套本仓库的登录表单和 Dashboard 保存校验扩展。
- Token、游标、绑定关系在 `data/plugin_data/astrbot_plugin_lajiaoliao/`。目录 0700、文件 0600，普通平台配置不含密码或 Token。
- 一个已授权账号只允许一个绑定；工作进程按会话持有操作系统文件锁。管理员手动复制数据目录不属于支持的部署方式。
- 一个运行账号一个 Go 子进程。动态回环端口、独立内部凭据、协议版本握手、校验和验证；凭据通过 stdin 传入，父管道关闭触发退出。
- 停用机器人、注销授权、插件卸载或重载会停止相关进程；首次未建立消息游标时从当前消息头开始，不自动回复历史消息。
- 收件 ACK 表示已交给 AstrBot 或被策略拒绝，不代表模型处理完成；内存队列不能提供崩溃场景下的严格 exactly-once。
- 每个适配器最多 32 个未完成处理任务，超过上限暂停读取下一条消息，不另起无限业务任务。
- 当前接入文字、文字引用、JPEG/PNG 图片收发及 GIF 收发；GIF 当前只通过指定群单向小动画验收，其他媒体和新增 @ 明确不支持。成员动作按实测门槛启用。引用原文仅在同账号、同会话最近 200 条内读取，不保存额外正文或改变游标；原文缺失或类型未支持时明确拒绝，不降级。IM Token 续期通过模拟测试，业务 Token 无效、被踢下线或设备确认需人工重新登录。

引用消息转换为 AstrBot `Reply`，包含原消息 ID、文字、发送者及时间；AstrBot 的引用解析器可将原文纳入模型上下文。模型回复是否自动引用由核心配置 `platform_settings.reply_with_quote` 控制，接入器不强制引用，不修改其他平台设置。插件或主动发送可传 `Reply(id=原消息ID)` 与 `Plain(回复文字)`；内部桥接也支持 `reply_to`，两种方式不可重复使用。

## 原实例重新授权与验收窗口

机器人编辑页的“重新登录”使用独立暂存目录及随机操作引用，只接受原 OpenIM 用户。切换时停止旧消费者并持有会话锁，仅原子替换凭据，不改配置或游标。授权结果可查询，取消和错误不覆盖原会话；原凭据在上游失效不能靠本地回滚恢复。

群管与完整机器人保存使用共同实例版本及锁，陈旧保存返回 409。兼容构建必须同时包含 `astrbot.core.platform.instance_control` 和对应 Dashboard 保存校验，不支持仅复制插件到未修改的官方版本。

`test-window` / `test-send` 默认关闭，需要明确账号、目标及确认。最多 300 秒和十次发送，先写操作记录，结果未知不自动重发。窗口不是平台授权，也不绕过消息策略。随包 `capabilities.json` 是协议证据矩阵，真实验收范围见 `ACCEPTANCE.md`。

## 撤回与群名片

群管页面不提供手动改名或撤回按钮。自身撤回供固定功能回复自动清理使用；自身名片接口保留历史协议能力。自动成员名片校验平台身份、逐群授权及当前名称，并保留原始名称防止前后缀叠加。上游没有原子条件更新接口，检查与修改之间仍可能存在并发变化。

固定动作 `revoke_self_message` 和 `set_self_group_nickname` 由当前实例权限、Dashboard 归属与版本校验保护。撤回仅查同账号、同会话最近 200 条消息；上游仍决定时限和权限。操作 ID 与回执保存在会话私有 `actions.json`，发送前持久化 unknown 状态，重复 ID 返回原回执，不重发。结果未知只查询或人工核验；页面关闭后可从操作记录找到 ID。账本最多 4096 项，满后拒绝新动作，不能直接删除旧 unknown 记录后重试。

系统 `2101`、`1516` 通知单独 ACK，不交给模型。撤回取消尚未完成的对应消息回复，并记录有界撤回标记以处理乱序；不能撤销已完成的模型调用、已发出的回复或承诺清除历史上下文。群名片通知更新有界名称缓存和群通知视图。通知视图只显示本次进程收到的新通知，不倒退游标重放历史。

## 兼容性与构建

当前实测环境为 Linux、AstrBot 4.28.1 及本次增加的通用 `astrbot.core.platform.message_policy` 扩展；不能把仅有版本号当作未修改官方版本的兼容承诺。没有通用策略扩展时插件拒绝初始化。

## 文字业务与管理命令

在群管页选择机器人、选择已保存开启的群，点击“刷新业务状态”。业务设置、发言排名、抽奖记录、每日通知、审核记录和能力对照分别显示。所有新业务默认关闭，保存设置不会开启活动或立即发送通知。完整迁移状态见 `FEATURES.md`。

- 发言排名只统计新鲜、已接收的成员文字，不统计命令、机器人、重复文字和待审核消息；同人计数间隔 30 秒，同文去重 5 分钟。按北京时间每日排名，每页 20 人；收到撤回通知后排除对应证据。保留最近 31 天的消息元数据与散列，不保存正文。
- 抽奖在自动化设置指定单次开始时间，到点自动开抽；群内“参加抽奖”报名。报名和开奖均核验有效邀请人数，开奖核验完整成员目录并排除机器人。参数及随机结果冻结，只发布一次，不重抽、不发资金；未知结果保留回执。
- 每日通知在自动化设置保存时间和内容，到点自动发送。新计划错过边界超过 30 秒暂停，不集中补发。旧任务保留恢复和原创建者校验，未知结果不重发。
- 审核默认只记录；Dashboard 明确开启当前群处罚规则和对应动作授权后才执行。旧模式只递进禁言，新撤回模式必须通过普通成员实测；违规审核不自动踢人。模型无工具、十秒超时、最多两个并发审核；失败只记录。内容模型的“允许”不能消除独立关键词/刷屏证据。模型 ID 必须引用当前 AstrBot 已配置的提供商。业务观察最多处理 16384 字符，超长正文不进入此业务；刷屏窗口只保留定长散列，模型上下文仅保留有界短文本。
- 管理入口支持当前有效 AstrBot 管理员，以及 Dashboard 显式授权的本群机器人管理员私聊；使用“群列表 → 选择群 编号 → 帮助”。被授权用户只看到此实例中自己获授权且已开启的群。普通成员管理命令返回无权限，群内保留排名、报名、抽奖状态和“我的权限”等公开查询。原生群主身份不自动等于 AstrBot 管理员。目录选择按实例、操作者和会话隔离，十分钟失效。
- 私聊 AI 只调用固定查询或生成配置草稿，须由同一管理员在原会话发送独立确认命令才保存。AI不能执行群动作、确认、授予管理员、开通动作或启用自动处罚。不接受任意 HTTP 接口、SQL、代码或资金动作；权限和设置版本发生变化则拒绝配置确认。
