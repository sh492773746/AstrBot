# v0.8.0 发布与回滚

## 公开源码归档

当前源码包含后续 v0.8.3。历史验收报告、账号与业务数据不随源码或运行包发布；
下文 `ACCEPTANCE.md` 仅指私有证据。兼容声明仍固定已验证的 AstrBot 4.28.1，
不是主仓库 4.29.0-beta.1 的生产兼容承诺。`--worker-only` 只构建离线测试程序，
不能把其产物当作依赖审查通过的正式运行包。本次提交不自动执行升级或回滚。

v0.8.0 增加人工套餐、共享预算账本、运营 TAB 和可选原生 Gemini 计量钩子。
产品规则、真实计费门槛和商业回滚限制见 `COMMERCE.md`。
首次加载本轮核心钩子需要短维护重启；仅重载插件不足以加载已缓存的核心模块。
两个既有实例仍为内部实例；本轮不新增真实客户，不自动生效费率。
新增商业账本、未知预留及只追加调用事件必须保留。
已有商业归属时，旧版本没有门禁的回滚备份会被拒绝，不能借回滚恢复付费实例。

支持范围固定为当前配套 AstrBot 4.28.1、Dashboard 扩展及内部协议 2。
`core-compatibility.json` 记录必要核心文件校验值；不是任意官方版本的即装插件。
Python 依赖见 `runtime-dependencies.json`，Go 依赖见 `go.mod`／`go.sum`。
生产启动只执行已构建并校验的 Linux 程序，不编译或下载可执行文件。

v0.6.4 只增加群内已绑定机器人互斥、只读忽略记录及绑定 UID 缓存；
无新设置或业务表，不修改权限、凭据、游标。回退本轮受限代码备份
会撤除互斥保护，安排回退时需先停用其中一个测试实例避免恢复互聊；
不得通过恢复旧配置或游标来消除已发生的对话。

v0.6.3 新增 `lottery.py`、固定校验和的 `assets/lottery-v1.gif` 和默认关闭的
`lottery.notify_results`。首次报名证据及逐步回执存放在新的账号私有表中；
不改变现有报名表、Token、游标、中奖记录，也不恢复未知发送。
未保存新字段的旧群设置可直接回退 v0.6.2。已保存新字段时，不可直接用旧版编辑：
先停用辣椒聊插件与消费者，保留当前设置及 SQLite 一致快照，再按审核过的转换
去掉设置中的 `lottery.notify_results`；新表和未决回执必须保留，不重新开奖。
不要通过恢复整个旧数据库进行回退。

v0.6.5 增加逐群 `group_ai_enabled`、`commands_enabled`，没有保存新字段的旧群
保留原 AI 行为、规则默认开启。热重载本身不改已有数据库设置或业务版本。
一旦保存新开关，v0.6.4 不识别这些字段，不能只恢复代码后重新启用消费者。
回退必须先停止辣椒聊，保留最新凭据、游标和账本，再审查转换后的设置；
旧版没有群 AI 开关，不能直接删掉关闭标记导致恢复 AI。需先在该群 AstrBot
独立配置文件中保持等价禁用策略，再按当前版本校验转换；无法等价转换时暂停回退。
不得恢复整个旧数据库或覆盖其他平台配置。受限新备份见 `ACCEPTANCE.md`。

## 升级

在 `/opt/astrbot-prod` 执行。下面仅作用于辣椒聊；新登录和重新授权请避开维护窗口。

```bash
.venv/bin/python services/lajiaoliao-bridge/backup_release.py
.venv/bin/python services/lajiaoliao-bridge/build_plugin.py
.venv/bin/python services/lajiaoliao-bridge/reload_release.py \
  --output /opt/lajiaoliao-migration-backups/release-check/report.json
```

构建会替换磁盘上的协议程序，但不启动新消费者；运行进程随后必须重载才能使用新程序。
不要在正在计时的长稳专项中构建或重载。先核对构建校验和与只读预检；
没有进行中的授权、抽奖或 90 秒内的任务边界时，再使用同一命令加 `--execute`。

重载只调用辣椒聊插件接口。检查主 PID、整个平台配置、账号绑定、群设置与版本保持不变，
并等待启用的实例恢复在线及每账号一个消费者。失败停止后续发布，不自动重试或回写凭据。
用户同时编辑配置时会拒绝继续；不覆盖用户修改。

最终运行包、协议源码包、兼容清单及核心策略补丁在 `services/lajiaoliao-bridge/releases/`。
执行 `sha256sum -c SHA256SUMS` 核对四项材料。运行包不包含账号数据、密码、Token、
游标、审计数据库或旧插件登录页面。
可以使用 `audit_release.py --output <受限报告文件>` 做只读资源和校验和检查。
构建先写私有临时程序再原子替换；相同程序不会替换正在运行进程的 inode。
归档时间戳、所有者和资源模式归一化，支持相同源码及环境的重复构建校验。

## 回滚到 v0.5.1

已存在商业归属时，本节旧版本流程拒绝执行；必须先暂停客户与实例，再使用
已审查且保留套餐门禁的代码备份。不能删除商业账本或先转换业务数据绕过门禁。
只有未产生商业归属的内部部署可继续使用以下历史流程。

先在机器人页面只停用辣椒聊实例，再停用辣椒聊插件，确认没有旧／新消费者或后台任务。
旺商聊、Telegram 及 AstrBot 主进程不需要停机。受限备份必须是已核验的 v0.5.1，
不能选一个名称相似但内容未知的目录。

```bash
.venv/bin/python services/lajiaoliao-bridge/rollback_v051.py \
  --backup /opt/lajiaoliao-migration-backups/image-automation-gvkxgy36
```

该命令默认只读；检查输出后使用同一命令加 `--execute` 转换业务设置。
它保留原设置与一致数据库快照、暂停新增任务，运行中或结果未知的操作不得重做；
旧版本不认识的新开关会移除，自动处罚和活动默认关闭。
旧版邀请跟踪与奖励未拆分，因此回滚会关闭邀请业务，并清零旧版不支持的邀请门槛；
原值保存在受限快照中，不删除既有积分或邀请记录。

```bash
.venv/bin/python services/lajiaoliao-bridge/backup_release.py \
  --restore-code /opt/lajiaoliao-migration-backups/image-automation-gvkxgy36
```

仅恢复代码，不恢复备份中的 Token、游标、全局配置或整个业务数据库。
保留最新凭据、绑定、未知回执和业务记录；重载旧插件后核对每个账号，再逐个启用。
若上游已经使旧授权失效，按创建／编辑机器人里的官方流程重新登录，不盲目恢复旧 Token。

新版本对旧设置增加独立账本和版本；不要跳过 `rollback_v051.py` 直接让旧解释器处理新设置。
所有备份目录 0700、敏感文件 0600。回滚副作用不可由取消开关自动撤销；
例如已执行的全员禁言必须核对现状，并由当前合法授权的新边界或平台官方客户端处理。
