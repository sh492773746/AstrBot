# 热播 Live 助手

## 0.2 权限与发送状态

主管理员固定为 Telegram 数字 ID `1000000001`（@example_owner）。旧 `admins` 白名单不再授权；其他人必须由主管理员在房间详情生成一次性邀请链接。链接 24 小时有效，服务端仅保存哈希，领取后绑定用户 ID，房间权限持续到撤销。授权管理可调整房间范围、撤销用户或撤销未领取链接。WebUI 仍只对 AstrBot 管理员开放。

房间详情显示主播、文案、间隔和最近 20 次发送结果。结果待确认时暂停，普通启用不可绕过，须主管理员核查后恢复。暂停后可删除配置，相关授权范围也会移除。移除使用者不停止房间已有任务。

状态格式升级到版本 2，保留房间、凭据和进度；恢复时重新等待完整间隔。房间轮询与发送任务分开，采用单调时钟、每房间一个任务、两路后台网络并发。状态超过 60 秒未更新时禁止发送。暂停和文案修改不等待后台网络请求，发送前复核配置版本；已提交的消息不可撤回。

页面展开房间查看详情，刷新保留输入焦点和未保存内容；未保存时禁止启用，保存成功后清除未保存标记。恢复操作不重发待确认消息。

轻量 AstrBot 插件：插件页面登录，Telegram 私聊 `/rblive` 管理直播间。无需注册、独立服务或数据库。默认没有账号，房间默认暂停。

## 配置与使用

1. 安装插件，在插件配置中填写专用 Telegram 平台 ID；由主管理员配置其他人的房间授权。
2. 打开插件详情 → 页面 → settings，输入热播账号密码。勾选记住密码时，仅保存到运行 AstrBot 的服务器插件数据目录。
3. 登录后点击“获取可见直播间”，设置文案和间隔，再启用；也可私聊机器人 `/rblive` 操作。
4. 每房间一条文案（最多 300 字），最多 10 个房间，间隔 30—86400 秒，默认 300 秒。开播、恢复、重启后均等待完整间隔。更新间隔重新计时，更新文案下一次生效。

账号、令牌和密码不会通过状态接口返回。退出会删除服务器凭据和会话，暂停全部房间。密码未记住时仅驻留内存，重启后仍可通过有效 refresh token 恢复。

## 运行行为

每 30 秒检查直播状态。只有可见且直播中的房间才发送。房间全员禁言可能允许管理员发言，以发送回执为准；平台明确拒绝发言时 30 秒后重试，不重复提交被拒绝的那条文案。其他个人权限拒绝暂停。登录状态无法确认时停止，管理员手动重新登录，避免争抢同一账号。未知刷新失败不会自动反复密码登录；此保守策略优先避免挤掉手机会话。

公屏使用 IVS，按请求 ID 等待回执；明确成功标记 confirmed，拒绝标记 rejected，超时或断线标记 uncertain 并暂停。请先核查直播间记录，再手动恢复。插件不发送入场消息，不保存聊天历史，不向工作群发运行通知。

使用时才打开聊天连接，发送并收到回执后关闭，降低空闲资源占用。最多一个发送在途。管理操作与发送序列化，网络超时后可继续操作。

## 数据与备份

运行目录 `data/plugin_data/astrbot_plugin_rebo_live/` 权限 0700；`state.json` 保存房间及发送进度，`credentials.json` 保存可选账号密码，`session.json` 保存令牌，文件权限 0600。凭据为受文件权限保护的明文，仅由服务用户读取，不进入普通插件配置导出。备份必须同等保护；退出清除不包含以前制作的备份。

停用插件后备份该目录。恢复时保持房间暂停并核查发送中状态。卸载/重载清理任务、连接、Telegram 处理器及插件 API。

# 私聊菜单与房间更新

每轮最多发送两条独立弹幕：第一条收到回执后等待 1 秒，再发送第二条；第二条留空时只发送一条。每轮完成后按房间配置间隔等待下一轮。等待期间暂停、删除或修改配置会取消本轮剩余消息；拒绝或结果不确定时停止发送，不自动重试。

发送 `/rblive` 或 `/start` 可展开底部键盘：我的直播间、运行状态、发送记录；主管理员另有授权管理。房间详情仍使用消息内按钮。每次操作都会检查授权。

平台的直播 ID 可能变化，插件按 `room_no` 关联已有配置，保留文案、间隔和授权；不会仅凭同名合并房间。旧配置缺少房间号时需先核对身份再补充。页面每 15 秒刷新状态并保留未保存编辑，Telegram 已发送的菜单是当时的状态快照，请点击运行状态查看最新结果。
# 多文案轮播与回执策略

间隔设置分为「每条间隔」和「每轮间隔」：每条间隔1—3600整数秒，旧配置默认2秒；每轮间隔30—86400整数秒，保留原配置（例如50秒）。后台及Telegram均可独立设置，修改后重新等待每轮间隔再继续。最后一条之后只等待每轮间隔，不叠加每条间隔；网络及回执处理时间另计。

文案不再限制两条。Telegram 点击「新增文案」，发送一条1—300字的文案即可追加，继续添加请再次点击。后台为逐条列表，提供「新增这一条」「保存此条」「删除此条」，删除需确认；不再要求用分隔符提交整份列表。修改使用版本校验，旧页面不能覆盖其他管理员的新配置。每条可包含换行，至少保留一条，传输大小仍受消息及管理接口限制。

一轮内逐条发送，每条处理完成后等待2秒；最后一条处理完成后，等待管理员设置的轮次间隔（例如50秒）再开始下一轮。网络连接、回执等待及调度可能增加实际间隔，不并发刷屏。旧 text/text2 配置自动兼容。发送前持久保存下一条位置；回执超时、连接异常或解析失败记录为未确认，不伪报成功，不补发该次尝试，也不因此关闭房间。重启不重放中断尝试。

明确的平台拒绝、登录失效及房间禁言保护仍保留。历史记录保留最近20次；轮播再次发送相同文案是新周期，不代表重试或确认旧尝试。升级不会自动启用原本暂停的房间。

发送准备阶段的 `room/info`、`room/generate-chat-token` 若返回 `2001011` 或 `2010132002`，分别等待30、60、120秒进行最多三次重查；持续失败才暂停，并显示具体接口及“未提交弹幕”。重查保留待发送位置与计时，连接恢复后继续正常轮播，不重发历史尝试。手动重新启用会重置重查次数，并重新等待完整每轮间隔。发送后的明确内容拒绝不适用此规则；回执不明仍不补发。“最近结果”是上一次实际发送的回执，不代表当前接口已恢复，也不代表公屏已核验。
