# 辣椒聊

辣椒聊在“创建机器人”中登录和完成官方验证；插件页面只负责群管。插件内部提供通信能力，权限、模型、人格、回复和会话配置由 AstrBot 管理。

## 源码与构建

群管插件源码在 `data/plugins/astrbot_plugin_lajiaoliao/`，核心兼容接入器在
`astrbot/core/platform/sources/lajiaoliao/`，Go 协议桥及维护工具在
`services/lajiaoliao-bridge/`。创建、编辑、消息控制页面及离线测试随主仓库提交。
`integrations/personas/xiaoman/` 提供配置工具依赖的静态人格和示例，不含聊天记录。

插件 v0.8.3 的已验证生产配套版本仍为 AstrBot 4.28.1、Linux、协议 2，
元数据和依赖清单保留该限制。主仓库版本为 4.29.0-beta.1；
源码集成和离线回归不代表这个新版本已完成真实登录、热迁移或生产验收。
不要仅复制插件到未修改的官方版本，不要为加载而绕过版本检查。

从仓库根目录执行 `python services/lajiaoliao-bridge/build_plugin.py --worker-only`
可为离线测试构建当前平台的协议程序与校验和，不检查或认证生产依赖。
正式 Linux 包使用匹配依赖的环境运行同一脚本、不带该参数。
CI 在 Linux/macOS 构建离线程序；插件依赖 POSIX 文件锁，
Windows 不收集其专用测试，跨平台消息策略和共存测试仍执行。
程序、构建产物、账号凭据、游标、业务数据库、线上验收报告不提交；
历史文档提到的 `*ACCEPTANCE.md` 属于私有证据，不随公开源码或运行包分发。
此轮源码提交不启用账号、不修改正式群规则，也不重启线上服务。

计费来源指纹改为使用当前供应商 API 密钥签名、带独立用途标识的 HMAC，
不再直接摘要包含凭据的配置；缺少密钥时拒绝计费。
旧指纹的费率快照不自动迁移或继续放行，须由有权限的计费管理员核对来源、
明确配置匹配的费率与订阅后再恢复计费调用。
此次源码发布不改写现有费率、余额或历史账单。

## 登录与绑定

在“创建机器人”选择“辣椒聊”，直接输入手机号、密码并点击“登录”，在当前弹窗内完成人工官方滑块验证。机器人 ID 自动生成；登录成功后自动关联当前机器人，不再填写会话引用或点击“确认绑定”。点击创建弹窗底部“保存”完成创建。
页面刷新后，在“创建机器人”中的“未完成的机器人”选择自己的草稿并恢复，或者注销不用的草稿。授权草稿有效期为 15 分钟。

支持不同账号多实例。授权草稿按机器人实例隔离，一个未完成的登录不会阻止创建另一台机器人；同一实例重复点击会继续原草稿。每位 Dashboard 用户最多同时保留 8 个未过期登录草稿，这是临时授权资源上限，不是已登录实例数量上限或容量保证。“取消本次登录”只清理尚未完成的授权，已经完成的登录要求先刷新结果，避免误删凭据。过期草稿仍自动清理。

密码只在当前表单内存中保留，验证码失败或取消时不会提交登录请求；成功、失败或关闭表单后清空。验证码位于不含 `allow-same-origin` 的独立沙箱，不向其中传递密码或 Dashboard 凭据。官方服务仍会验证滑块证明；加载出滑块不等于真人验证和登录已验收。主面板经 HTTPS 调用插件，Go 服务继续只监听回环地址，无需为新流程转发本地端口。

新建机器人默认停用，群列表为空、私聊关闭。同一账号不能重复绑定；请求超时后先点“刷新登录状态”，不会自动重发密码。已有有效会话显示“已登录”；未保存的授权在创建表单中恢复或注销，无需输入机器人 ID。历史孤立绑定只能恢复为原实例 ID；已被现存机器人占用的会话不能注销。创建取消不会自动注销已完成登录的会话，重新打开创建表单可处理。

插件入口仅有“辣椒聊群管 → 群聊管理”（`management`）。旧 `accounts` 页面已撤除；插件内部 ID 与数据目录不变，不迁移或重置现有账号。

## 原实例重新登录

编辑已创建的辣椒聊机器人，点击“重新登录”，填写原账号并点击“验证并重新登录”，在当前页面完成官方滑块。只允许同一 OpenIM 用户；手机号不是会话身份的替代值，换号必须新建机器人。

重新授权独立暂存，15 分钟失效，不建立第二个消息消费者。成功切换只替换凭据，保留原机器人 ID、会话引用、启用状态、消息游标和群权限。取消、失败或账号不匹配不会覆盖原凭据；官方登录可能使旧设备授权失效，本地保存旧文件不保证恢复官方会话。

请求超时先点“刷新登录状态”，系统可核对已保存的授权结果，不自动重新提交密码。官方返回设备确认时仍需用户在官方客户端确认，不自动夺回设备。被踢下线或业务 Token 无效会要求人工授权。

运行期仅在明确的 OpenIM Token 到期错误下使用有效业务 Token 获取新 IM Token，刷新请求合并并检查凭据版本；普通网络错误采用最长 30 秒退避，不冒充 Token 到期。模拟测试通过，不代表辣椒聊私有服务端的真实过期流程已验收。

## 群聊与私聊

入口：机器人 → 辣椒聊机器人 → 接入设置 → 消息控制。旧版“群聊范围”三选项已改为固定白名单 `allowlist`，空列表禁止全部群聊。

也可以在“辣椒聊群管 → 群聊管理”选择机器人，分别设置群开关和私聊权限。只显示当前 Dashboard 用户拥有且已创建的绑定实例。群管与机器人完整保存共用实例版本，旧表单返回 `409`，必须刷新后重新编辑。该页保存即时更新运行实例，不重启消息连接，不启用停用的机器人。

群管支持浅色/深色主题和手机布局，顶部选择当前机器人，底部统一保存权限。

- “刷新群列表”只查询当前会话所属账号的群目录。机器人停用时使用临时只读进程，不连接消息流、不发送消息。目录超过一页时使用“加载更多群”。
- 每个群有独立开关，可以按群名称或 ID 搜索，也可以手动添加群 ID。添加并开启仅修改编辑草稿，点击“保存更改”后才生效。
- “允许私聊”是独立总开关，新建机器人默认关闭。已有机器人的私聊设置保持不变。
- 保存群设置不会自动启用机器人。群开关同时约束入站处理、回复和主动发送，允许后仍受原有权限和唤醒检查约束。
- 不同群的模型、人格等使用下方“会话配置”中的独立配置文件绑定。此处群开关不包含禁言、踢人等平台管理权限。
- “辣椒聊群管 → 自动化设置”提供每群“群 AI 聊天”和“规则命令识别”。新群 AI 默认关闭、命令默认开启；已保存旧群未配置 AI 字段时保留原行为。群 AI 同时受当前 AstrBot 配置文件总开关、会话启停和唤醒规则限制；关闭它不会关闭审核或固定业务命令。
- 私聊管理员依据该实例逐群 UID 授权识别，唯一授权群自动选中；多个群仍需“群列表 → 选择群 编号”。撤权立即影响后续检查，不授予全局管理员或原生群管理员权限。
- 百群使用有界处理：每账号 32 条在途、四个数据库工作、64 个已接纳数据库操作、有界配置缓存及最多四个账号计划轮询；达到上限等待，不静默丢弃。离线模拟不是生产模型吞吐承诺。

旧 `deny_all` 保存时转换为 `allowlist` 加空列表，不会扩大权限。直接提交 `all` 的辣椒聊配置被拒绝；其他平台保持原行为。

## 与旺商聊的能力边界

| 功能 | 当前情况 |
| --- | --- |
| 登录、会话隔离、绑定 | 已实现；人工验证仍由用户完成 |
| 群白名单、逐群开关、私聊总开关 | 已实现，使用 AstrBot 核心策略 |
| 逐会话模型、人格、配置路由 | 复用 AstrBot；真实账号消息仍需验收 |
| 群目录、分页 | 已实现只读入口；实际账号返回内容仍需核验 |
| 私聊、群聊文字 | 协议已有实现，模拟收发通过；不能替代真实目标验收 |
| 文字引用回复 | 已实现接收转换与发送，验收范围见插件记录；原文仅在同账号同会话最近 200 条中查找 |
| 撤回自己的消息、修改自己的群名片 | 历史原生能力保留；自身撤回供授权的功能回复自动清理使用，不恢复手动按钮 |
| 图片 | 两账号群聊及私聊 JPEG/PNG 双向八次实测通过；GIF 在测试群单向发送并确认原生 102 及对端 AstrBot Image 交接；GIF 私聊／反向发送和图片引用尚未验收 |
| 语音、文件、视频、新增 @ | 本轮不接入，明确拒绝 |
| 自动审核、递进禁言、群作息、功能回复撤回 | 已实现，逐群默认关闭；真实普通成员处罚仍待验收 |
| 成员撤回、自动名片 | 协议及规则已实现，开关须通过对应真人实测 |
| 封禁／注销清理 | 服务端可靠状态尚缺，开关不可启用；不按昵称判断 |

能力证据保存在插件随包 `capabilities.json`，包含接收、发送、动作和真实验收状态。客户端出现 SDK 方法只能说明存在协议线索；不能据此认定桥接已支持，也不能将“待验证”写成“平台不支持”。

## 引用回复

入站引用保留新消息正文，并转换为带原文、发送者和时间的 AstrBot `Reply`。出站使用 `Reply(id=原消息ID)` 加文字，或内部桥接 `reply_to`；不接受外部伪造原消息对象。自动引用由该会话核心配置的 `platform_settings.reply_with_quote` 开关控制，不需要修改其他机器人或全局配置。

首次支持引用文字及已引用消息的文字正文；引用另一个引用时按客户端语义展开为一层。原文超过最近 200 条、不在当前会话、类型未支持或查询失败，返回明确错误，不当成普通消息发送。历史查询不移动消费游标、不触发历史消息模型回放。

## 受控验收

顶部统一选择机器人和群，以 TAB 分区管理。手动群操作不再提供；自动化设置保存群作息、20 秒功能回复撤回、单次抽奖和每日通知计划。时间按北京时间，保存只安排未来任务，错过边界超过 30 秒暂停。未知结果不重试，任务每次执行重查原授权来源。普通成员撤回和名片开关须先实测，管理员与绑定机器人仍受保护。

系统撤回、名片更新通知不会送给模型；撤回可阻止尚未完成的对应回复，无法收回已经发出的回复或抹除已经完成的模型上下文。操作回执按账号持久化，未知结果不自动重复。新通知仅显示本次连接收到的内容，历史游标不重置。

内部插件接口 `test-window` 和 `test-send` 默认不允许测试发送。开窗必须确认当前账号并显式指定最多四个私聊或群目标；最长 300 秒、最多十次发送，仍须通过原消息策略。测试操作先持久化，重复操作 ID 返回已有回执，结果未知不自动重发。接口不代替正常消息策略，不绕过官方验证和平台权限。

本部署已指定两台测试机器人和“测试群”72567012，可用于图片及实例隔离验收。真人排名、邀请、报名和处罚仍需明确普通测试成员；不能豁免机器人保护来代替这些验收，不进行整机网络中断测试。

v0.6.2 保留 JPEG/PNG 群聊及私聊收发验收，并新增 GIF 出站：745 字节、64×56、6 帧测试图已由指定测试群单向发送；原生 `102/type=gif`、大小和接收端 AstrBot `Image` 交接一致。GIF 私聊及反方向尚未验收。GIF 接收样本已观察到原生格式，完整实时接收交接仍待用户重发确认。图片限制 20 MiB／4000 万像素，GIF 最多 120 帧且总解码像素不超过 1 亿，最多两个媒体任务，只信任经核验的精确官方 HTTPS 域名，所有重定向和 DNS 重新检查。动画 PNG 和其他格式拒绝；音频、文件、视频及新增 @ 不在本轮范围。

不要直接复制旺商聊的群管业务到通信插件。后续若验证了对应协议，应通过能力声明和独立业务层接入，保留角色校验、明确确认、审计和未知结果处理。真实发送和群管理验收需先明确目标群或联系人。

## 非容器运行边界

同一管理员管理的受信任账号可以使用独立协议进程，无需为每个机器人运行一个容器。协议进程独立不代表操作系统权限隔离：主服务及其插件仍可能拥有读取其他账号文件的权限。

管理操作按账号加锁，不同账号的慢目录请求不再占用共同的排他锁。进程启动和目录查询分别最多并发 4 个，单个内部 HTTP 会话最多 8 个连接，状态查询超时 3 秒、目录查询超时 10 秒。不同账号仍共享主进程、模型服务和机器资源。

离线复测：`PYTHONPATH=. .venv/bin/python services/lajiaoliao-bridge/plugin_stability_test.py --seconds 120 --workers 4`。该测试不使用真实凭据，也不连接上游消息流。真实多账号容量、长期稳定性和故障恢复需另行验收，不能用本地状态接口耗时替代模型回复延迟。
