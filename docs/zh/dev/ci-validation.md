# CI 验证

完整 Python 测试在 Linux、macOS、Windows 上各分成四片，按模块确定分配，
保留模块内的夹具与执行顺序。Windows 失败会阻止通过；不会为凑绿排除原有
文件、标记或测试档位。每片保存用例清单、JUnit 和输出日志，最终检查拒绝
漏片、重复用例及不一致的收集结果。

覆盖率同样运行完整用例，分为四个有时间及资源边界的 Linux 任务。只有四片
全部通过、清单恰好覆盖一次完整收集结果，才合并覆盖率数据库并生成 XML。
取消或超时不能算通过。

安装开发与 WSL 依赖后，可以复现其中一片：

```bash
ASTRBOT_CI_SHARD_INDEX=0 ASTRBOT_CI_SHARD_COUNT=4 \
  uv run python scripts/ci_pytest.py tests -q
```

不设置分片变量就是单进程完整测试。看门狗直到日志刷新完成才取消，
避免残留线程持有日志锁后让工作流无限等待；进程仍返回 pytest 的真实退出码。

离线连接拦截在 asyncio 事件循环启动后安装，避免误拦 Windows 用 TCP 建立的
内部唤醒连接；测试正文主动连接本机也仍会被拒绝。大型二进制参数使用简短、
明确的用例名或长度与摘要标签，原始测试数据保持不变，避免超过 Windows 环境
变量长度上限，也避免兆字节长日志堵塞云端采集。私有权限测试在全部平台
核实权限设置调用，在 Unix 额外核实真实权限位，不把 Windows ACL 冒称为
Unix 权限。成员目录强制刷新用固定时钟回归，确保串行的新核验不会被误当成
并发合并读取而使用旧目录。
财务测试窗口直接检测同锁重复获取，并注入共享锁回归验证检测有效，
不再以云端 SQLite 初始化耗时推断死锁。
HTTP 超时阶段测试先由本地服务确认收到请求，再在响应头等待期间触发超时，
不再假定 TCP 连接能在 30 毫秒总期限内建立。

CodeQL 告警通过修复代码解决，不以排除查询、关闭告警或放宽分支保护来通过。
路径必须先标准化并核实仍位于允许目录内，符号链接也不能越界。
删除时校验真实父目录，但保留选中的目录项，移除符号链接不会删除链接目标。
仅在勾选删除配置或数据时检查对应路径，保留的数据不会触发清理校验。

AI 头像的凭据校验格式变更涉及已付费的远端任务。旧任务保持原任务号和额度，
由存储首位超管明确核对后恢复轮询，不允许自动重新提交。维护入口与前提见
插件 README 的 Credential Verifier Maintenance 小节。
