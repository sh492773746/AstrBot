Git与验收边界

推送前核对目标仓库、可见性、分支、远端历史及提交作者。 本地独立基线不能强推覆盖已有远端主分支；使用独立分支并保留可审查的差异。 当远端另含本机没有的插件或新版本时，本机生产快照必须放入独立快照分支， 不能将整个生产树覆盖到远端主分支，也不能将“快照已上传”说成“主分支已合并”。 提交后检查Git索引无遗漏；推送后比较本地提交SHA与远端分支SHA， 并核对关键模块、管理页和文档能从远端提交读取。 没有远端地址、写权限或可靠回执时，明确报告未上传，不能写成“已提交GitHub”。

离线回归、构建、配置读回、真实收件、平台处罚和手机显示是不同证据层级。 2026-10-23 23:39的名单移除与三群7天配置对齐没有执行真实处罚； 产品默认仍为29天。2026-10-24起，群内原生管理员真实@单个成员或回复可核实的同群原消息发送“黑名单”， 按当前群配置立即提交禁言；私信和后台加入仅登记，后续可信真实重入才禁言。 相同命令不重复处罚，未知结果不自动重试，黑名单流程不踢人。 不要因文档更新或仓库上传而修改正式群规则、启用测试账号、开放窗口或重试未知动作。

English Release Boundary

Publish the complete adapter, plugin, dashboard sources, required static assets, build inputs, shared-core wiring, tests and bilingual documentation together. Keep credentials, sessions, production databases, customer content, uploads, private backups and rebuildable caches out of Git. Regenerate guides and PDFs from maintained sources; built pages do not replace their sources. Use a reviewable branch when local and remote histories differ, never force-push over a remote default branch. Verify the remote commit SHA and key paths after upload. A Git commit or successful build is not live-sanction acceptance. The latest seven-day setting is scoped configuration, not the29-day default.
