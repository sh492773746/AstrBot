旺商聊接入 AstrBot 完整测试流程

历史归档：以下保留早期流程与当时验收记录，包含已变化的能力、命令和部署状态。 不作为当前操作手册。请使用现行测试与验收。

版本日期：2026-09-19。本文是可执行验收流程，不代表各项均已通过。

1. 目标、角色与判定

验证配置从页面编辑、保存、磁盘持久化、运行时加载，到真实消息行为的完整链路。测试同时覆盖登录、目录、消息、群管、媒体与长期稳定性。

角色 当前对象 用途
机器人 A wangshangliao_3cf3b038 第一组配置与收发测试
机器人 B wangshangliao_809ac622 对照配置、隔离及互斥测试
普通账号 C 执行前记录已指定测试账号的脱敏标识 向机器人发送消息及确认收件
测试群 G1 大海兼职群；执行前核对业务群 ID 群回复及已指定群管测试
测试群 G2 执行前另行指定 多群隔离；未指定则记为阻塞

A、B 属于同一 AstrBot 管理的机器人，默认互斥。它们适合测试配置隔离和“不互相回复”，不能充当普通用户证明正向回复成功。缺少 C 时，不解除互斥；普通用户正向收发记为阻塞。

判定统一使用：通过、失败、阻塞、未执行、不适用。接口返回 200、页面显示在线、服务端 accepted 均不能单独证明消息送达。

2. 测试准备与还原

  1. 记录代码提交与未提交改动范围、Python/Node 版本、操作系统/架构、前后端构建版本和服务启动命令。不要在验收过程中改模型或推理参数。
  2. 记录 A、B 当前启用状态、群列表、私聊回复、各群回复、主动发送、群管动作授权、关键词和冷却配置。
  3. 将当前配置和必要的会话数据备份到仅当前用户可读的位置；备份包含凭据，不附入报告、不上传、不输出全文。
  4. 确认两账号在线，测试群与普通账号身份映射明确。记录测试群公告、全员禁言、成员禁言的原状态，以便还原。
  5. 所有消息使用唯一编号，例如 WSL-20260919-R01-A-001。使用不含敏感信息的测试文本，暂停可能干扰结果的既有定时任务并记录原状态。
  6. 打开机器人页面、AstrBot 日志页及普通账号 C 的客户端。记录操作开始时间；日志只收集实例、阶段、关联 ID 和结果，不收集凭据或完整聊天正文。
  7. 每个阶段结束恢复测试前配置。发生异常时先关闭测试主动发送/自动化，再处理未知操作；不要通过重新发送来猜测结果。

3. 配置保存与刷新矩阵（优先执行）

以下矩阵对“允许回复私聊”“允许主动发送和定时消息”“启用机器人”分别执行，每次只改变一个字段。每群回复使用 G1/G2 额外执行；群管总开关采用无关键词、无动作触发的配置测试。

轮次 A B 重点
P1 开 关 独立保存
P2 关 开 反向切换
P3 开 开 无账号间配置覆盖
P4 关 关 关闭值不会被默认值替换
P5 原始值 原始值 还原

每一轮严格执行：

  1. 在页面选择 A，修改目标字段并点击保存，记录成功或错误提示；再对 B 操作。
  2. 切换 A → B → A，核对开关、已选群和保存提示。未保存状态不能显示为已保存。
  3. 浏览器刷新，等机器人配置加载完成后核对；“选择一个机器人”、加载指示或空白中间状态不算通过。
  4. 重新打开 /platforms，再次选择两个机器人核对。
  5. 使用当前 Dashboard 鉴权读取 GET /api/v1/bots/by-id?bot_id=实例ID，仅比较目标字段；与磁盘 data/cmd_config.json 中对应实例比较。禁止在工具输出中打印完整配置。
  6. 通过已知服务启动方式重启 AstrBot，等待启用实例上线；停用实例应保持停止。再执行步骤 2–5。
  7. 运行本字段对应的行为用例：回复、主动发送或停用。保存状态一致但行为不同，判为运行时加载失败。

通过标准：页面、GET 返回、磁盘及重启后的行为四层一致，A/B 不串配置。保存失败必须提示失败并保留可重试编辑；不能默默恢复旧值。

附加用例：修改但不保存后切换机器人，应有放弃修改提示；取消切换保留编辑。目录刷新失败时保留已选群，不把不可用当空列表保存。多群保存应去重且保留每群独立回复/动作设置。

4. 登录、短信、连接与退出

编号 步骤 通过标准
L1 密码登录，完成验证并保存 临时认证与保存连接分开显示；保存后对应实例在线
L2 短信登录，获取并输入用户收到的验证码 无须密码；创建方式显示短信登录，刷新仍保留
L3 验证失败、验证码错误/过期、重发冷却 明确分类提示；不把登录拒绝显示成滑块失败
L4 验证组件失败或超时 人工验证入口可用；取消/超时释放工作进程，无无限重试
L5 A 登录或重新连接期间查看 B B 不被登出、不被替换身份
L6 关闭启用机器人并保存，再开启 停用不处理新消息；会话保留；开启按恢复结果显示状态
L7 退出测试账号，再登录 本地恢复会话清除；旧事务和旧身份不再用于发送

L7 会改变登录状态，应在其他测试完成并具备重新登录条件后执行。不直接删除会话文件模拟正常退出。

5. 私聊、群聊及机器人互斥

每项发送前确认入站编号唯一。收到消息后观察至少 60 秒；若后台仍在处理，继续按当前模型超时配置等待，不以固定等待结束冒充“无回复”。

编号 条件及操作 预期
M1 A 私聊回复开、B 关；C 分别私聊 A 回复一次；B 不发自动回复
M2 交换 A/B 开关，刷新并重启后重复 结果相反，证明运行时不是旧配置
M3 G1 回复开，C 明确 @ A A 回复一次
M4 G1 回复关，C 明确 @ A 无自动回复
M5 G1 回复开，C 发普通文本或仅 @ 其他成员 无自动回复
M6 G1 开、G2 关；分别 @，然后交换 各群独立生效；未启用群完全不处理
M7 A/B 互发私聊，或在测试群互相提及 不触发彼此 AI 回复或关键词群管，不出现循环
M8 重复投递同一平台消息 ID 仅一次处理和发送；仅正文相同但 ID 不同不算重复投递
M9 群列表为空，C 私聊 仍按私聊开关处理，群消息不处理

M7 使用正常客户端和已指定测试目标触发，不改互斥代码。核对 ignored_bot 与出站记录；没有回复但没有收到入站消息，不能证明互斥有效。

6. 主动发送与定时任务

通过实际 Context.send_message() 调用链测试，并记录目标 UMO。调用入口缺失时记为阻塞，不通过临时绕过发送服务来验收。

  1. 开关关闭：向已知 C/G1 主动发送唯一文本，应拒绝且无出站网络发送。
  2. 开关开启：向已知、已启用目标发送，记录调用结果、outbox 状态、平台返回及对端是否收到。
  3. 无匹配平台、错误会话格式、未知私聊身份、未启用群、机器人 A/B 互发均须明确拒绝，不绕过身份校验。
  4. 保存关闭、刷新和重启后重复步骤 1，验证撤销生效。
  5. 完整目标授权实现后，验证允许目标通过、未授权目标拒绝；当前只有总开关，不能将这一项标为通过。
  6. 完整操作 ID 实现后验证：同 ID 同目标同内容不重复发送；同 ID 改内容或目标拒绝；新 ID 同正文可以作为新操作发送。
  7. 定时任务使用任务 ID 与计划时间作为稳定执行身份；测试正常执行、重试、停机错过、重启及执行前撤销授权。错过任务不集中补发，未知结果不自动重发。
  8. 注入发送超时或进程中断后检查 outbox，确认未知发送不会盲目补发；仅在隔离测试服务执行故障注入。

当前已知限制：send_by_session() 使用会话和正文生成键；不具备完整操作 ID、按目标授权及结果查询。能力元数据仍声明不支持主动消息；私聊 UMO 格式和工具发现链路也需验收。因此总开关持久化通过，不等于主动发送/定时任务完整通过。

7. 目录与身份映射

  • 群选择覆盖自动加载、刷新、搜索、多选、保存、切换账号和断网失败保留选择。
  • 成员分页覆盖多页、边界页、重复成员、同业务 ID 不同 NIM ID、不同成员共用 NIM ID、循环游标、hasMore 无游标、第二页失败及分页上限。
  • 群管目标位于第二页时应能查到；目录不完整或身份冲突时不得执行动作。
  • 私聊目录分别记录云端会话、联系人、本地已知会话来源；本地白名单 unsupported_route 不作为远端接口不存在的证据。
  • 云端接口未确认时显示待验证；刷新目录不能拉历史正文或触发 AI。云端目录未实现的测试标记阻塞，不用本地会话数量替代云端完整性。

8. 群管与媒体

群管只使用已指定 G1 和测试成员。先记录原状态，再按单项执行：禁言 → 状态回读 → 解禁 → 状态回读；公告使用已指定的 123123123；全员禁言测试结束恢复原状态。禁止将其他成员作为替代目标。

验证动作授权开/关、机器人原生管理员权限、目标角色保护、身份冲突、重复操作 ID、参数变化、关键词冷却、断线超时及重启。聊天内容不能授予权限或直接开启群管。accepted 但无回读依据只能记“已接受、未确认”。清理公告时遵循平台正常可恢复方式；无清理能力则记录保留的测试公告。

媒体按图片、文件、语音、视频分别测试上传、接收、下载、组件解析、对端展示、大小上限、超时、重复消息及临时文件清理。使用无敏感内容的小型测试素材。协议未实现时应明确拒绝，不能转成文本后宣称媒体通过。

9. 故障恢复、Linux 与 24 小时验收

  1. 在隔离测试部署断开连接再恢复；不影响整台主机其他网络。检查退避、恢复事件、重复工作进程与消息去重。
  2. 分别在空闲、处理中、发送结果未知时终止测试进程并重启；不得盲目重发未知结果或重复模型生成。
  3. Linux 在目标架构重新安装依赖，验证 Node、OpenCV/ONNX、资源路径、超时清理、登录、目录和收发，不复制 macOS 虚拟环境。
  4. 开始连续 24 小时观察前记录起点、版本与配置；每小时记录连接状态、重连次数、错误分类、内存、工作进程数和未知发送数。监控本身不发送测试消息。
  5. 期间按约定时点由 C 发送少量唯一编号消息，检查重复率和收件；不得用 A/B 自动互聊制造负载。
  6. 记录续期实际发生时间及恢复结果。24 小时未发生续期，续期项目仍标为未验证。意外重启后重新计连续运行窗口，保留原记录。

11. 每项功能独立启停验收卡

本节是第 3 节的细化执行表。每项均完成“关闭负向 → 开启正向 → 再关闭 → 浏览器刷新 → 服务重启 → 恢复原值”；A/B 交换承担执行者和对照者。每一步记录页面值、API 值、磁盘值、实际行为及收件证据。未实现能力不可用总开关测试替代。

11.1 组合依赖测试

  • 机器人停用但回复/主动/群管子开关开启：所有运行行为仍应停止；任何旧对象能继续发消息都记失败。
  • 群未接入但该群回复/动作授权残留：不能处理或执行该群动作。
  • 群回复关闭、关键词群管开启且授权：分别记录“未自动回复”和“群管规则是否执行”；回复与群管不是同一个开关，不将关闭回复当成关闭管理。
  • 群管总开关开启但动作未勾选：仅该动作拒绝，不能因平台管理员身份绕过本地授权。
  • 本地动作允许但平台不是管理员：拒绝或返回可解释的平台拒绝，不显示已确认。
  • 私聊回复关闭、主动发送开启：被动私聊不回复，显式主动调用按主动策略判断；不能混淆两种来源。
  • A/B 配置不同：保存 A 后重新读取 B 全部非凭据设置，确认没有复制、重置或串号。
  • 保存过程中撤销权限：记录请求开始、配置提交、操作提交时间；提交前必须重新核验，已被平台接受的动作不声称可撤销。

12.4 生产停止条件与恢复优先级

出现非测试目标收到消息、A/B 循环回复、重复管理操作、错误成员被操作、身份串号或登录互相抢占时立即停止该场景。先停相关主动/自动规则，保留证据，再恢复受影响成员和群状态；不要删历史日志掩盖问题。

出现普通连接错误时记录实例、错误分类和退避恢复情况；禁止反复重新登录导致两个实例争抢会话。若只有 A 异常，保持 B 原业务设置，不自动扩大 B 的授权。

结束必须检查：A/B 原配置恢复、测试群原禁言状态恢复、C 可正常发送、测试任务不再执行、两账号连接状态符合原设置。任何未恢复项单独列出负责人和下一步。
