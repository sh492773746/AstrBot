原生对话、统计与追踪

真实AI交互统一出现在AstrBot“数据与日志 → 对话”，按机器人ID及私聊／群聊筛选。 私聊咨询、群内@和自主闲聊分别隔离，关联同一次调用的Token统计与脱敏追踪； 群@新键为platform:GroupMessage:account/group/wsl-ai/account/group/mention/verifiedUid/peer， 只带入该键下配置允许的本人历史，不跨成员、群、账号或私聊，不迁移旧群客服咨询历史。 自主／冷场保留原/wsl-ai/account/group来源与原有短期候选缓存。 记录选中人格及实际问题、已发送的回复，不记录系统提示、知识参考片段、密钥、 工具结果、财务输入、普通命令或整批旁观消息。静默决策有模型统计，但不伪造聊天回复。 私聊记录最多保留所选上下文轮数（关闭上下文时保留本次问答），群AI原生记录最多20轮； 群@模型上下文另受群配置轮数限制，0不读取往轮问答。 记录使用原生后台查看、删除和导出，不新增插件对话库；写入前发现后台记录已删除、切换或编辑时跳过旧快照。 /exit、闲置结束或进入结账会结束咨询；下一次/chat使用新的原生对话， 不会把上一次后台记录重新喂给模型。后台历史不会因退出咨询自动删除，可在原生对话页删除。 既有插件临时历史不导入、不伪造回填；未通过模型门禁时不会为了填充页面发起调用。

配置、人格、模型凭证、中文检索分词、技术日志、对话、统计与追踪复用AstrBot原生能力。 个人／群知识的独立归属与版本检查、共享套餐费用预留、财务事务以及固定定时禁言的 逐群授权与执行回执继续由业务模块负责，不改成可调用工具或任意代码的原生Agent任务。 原生对话录入失败只在AstrBot记录脱敏警告，不重复模型调用或发送回复。

独立人工返现登记入口见邀请返现结账页。 现金账本与积分、抽奖分离，初始关闭；现有后台入口不变。 群内“我的邀请”与“邀请奖励”展示本群活动统计，私聊“我的邀请”仅查本人现金返现。 AI不读取实时账本。积分奖励未开启时显示“每人奖励：管理员未设置奖励”。

部署

使用 Python 3.12+，在项目根目录执行：

uv sync --extra wsl
cd dashboard
pnpm install
pnpm generate:api
pnpm build

内置滑块组件需要 Node.js 和 OpenCV/ONNX，按需启动串行本地工作进程，无需 GPU。 Docker 构建需启用项目的 INSTALL_WSL 构建参数。依赖在目标系统/架构重新安装， 不能复制其他系统的虚拟环境、EXE、DLL 或 .pyd。部署入口存在不代表所有架构均已实测。

由部署管理员设置 ASTRBOT_WANGSHANGLIAO_CONFIG 指向受保护 JSON 文件：

字段 要求
origin HTTPS 服务根地址
headers 协议请求头映射
metadata 14 个整数
signing_seed、body_key、message_key、server_key 标准 Base64 编码，解码后各32字节
captcha_id、app_key、device_id 有效协议部署参数
protocol_version 新登录的协议版本；2.8.3为桌面兼容协议，3.7.3为安卓协议，省略时保留3.7.1兼容；已保存会话按自身版本恢复，不直接转换凭证

Linux/macOS 文件应为 0600；Windows 使用仅服务账号可读 ACL。参数不得写入教程、 聊天或截图，也不从浏览器接口返回。缺失为 deployment_missing，不合格为 deployment_invalid。旧配置缺少 message_key 可以认证，但消息启动报 message_key_missing，不能把登录成功当收发就绪。

未设置环境变量时可加载已批准导入的 data/platform_data/wangshangliao/deployment/ 密封配置；显式路径无效时不静默回退。 导入协议配置不导入旧账号密码或账号会话。

ASTRBOT_YIDUN_SOLVER_URL 未设置或为 builtin 时使用内置求解器； 空值使用人工流程；外部 HTTP 求解服务为兼容选项。自动失败保留人工验证。 .venv/bin/python scripts/check_wangshangliao.py 做不联网、不打印凭证的预检， 预检通过不等于真实平台验收。

登录、保存与停用

  1. 机器人页创建旺商聊实例，选择密码或短信登录，完成滑块及设备短信验证。
  2. 官方3.7.3要求本次登录验证安全码时，后台会显示独立的安全码输入框。只在此处输入，不要发到聊天；不会保存安全码。若平台未要求，不必填写。
  3. 完整认证成功后在十分钟登录事务期限内保存登录并连接；公共模式群开通走群管理，不靠登录页选群授权。
  4. 等待消息连接“在线”，分别配置私聊/逐群回复、动作授权及主动发送目的地，再保存。
  5. 空启用群列表不处理群消息，仍可按配置处理私聊。

1400是平台认为未设置安全码，1402是本次登录尚未验证，不能混为一谈； 1403错误后至少等待30秒，1404锁定时先在官方App核对，1405先绑定手机号。 验证成功但消息令牌读取失败时，仅重试消息连接，不再次提交安全码。 验证结果不明时停止重试，取消后重新登录；不要在后台、日志或截图公布安全码。 安全验证成功回执不要求强制更换登录凭证：优先使用响应头的新凭证，其次使用 成功正文的新凭证；未提供新凭证时保留本次登录凭证，继续获取消息令牌。 没有新凭证、或新旧凭证相同，不应被误判为安全码错误。明确失败、损坏的响应 或网络结果不明仍停止，不重发安全码；消息令牌未确认前不能保存为认证完成。

新版密码、短信登录均提交已核验发布包对应的 version、appVersion 和 appHash，并非只更新请求头。3.7.3 对应版本号为335；发布包变化需重新核验， 不能根据文件名猜测或沿用旧包摘要。1001 是官方通用错误，不代表密码错误、 账号封禁或安全码错误；后台保留数字错误码，不记录上游原始响应或凭据， 也不会自动重试登录。离线测试通过不等于真实账号重新登录成功。

登录事务绑定后台用户与预分配实例，保存后才持久绑定账号并连接 NIM。 认证成功、配置保存和消息在线是三个独立状态。后台密码不等于旺商聊密码。 接入页“业务运行中／业务暂停”和“已启用群”读取该实例的实时业务状态， 不是从不含业务字段的登录配置推断；尚未读取状态时显示“业务状态待核实”。 接入页同时显示当前连接的原因及处理建议；未读取到连接或启用群数时显示“待核实”， 不直接当作离线或0群。错误详情入口显示“历史错误记录”，在线恢复后仍可保留历史记录， 不代表当前仍然故障。未知错误只显示固定说明，不将平台原始响应作为提示输出。

页面状态或提示 含义与处理
认证成功，等待保存 仅认证完成；保存后才会连接，不要重复登录
账号已在线 消息连接正常，无需重新登录；不代表所有群功能都已开启
正在连接或重连 暂未就绪，按间隔恢复；不是密码错误或封号结论，恢复前暂停群内操作
平台限流，等待恢复 遵守平台等待时间；不要连续点击登录或刷新
消息连接已停止 没有运行连接；停用保留会话，按需启用并保存，不要直接删除实例
会话失效 重新登录；不将普通网络中断误报为会话失效

连接状态／业务状态待核实 尚未取得可信状态，不推断登录失败、封号或空配置

业务暂停以实例实时开关为准，不能由“0个运行群”或账号离线反推。 运行群数只计已开通、在群、未暂停且成员核验无待处理状态的群； 未通过开通核验或容量暂停的群不计入，不能只数已保存的群记录。 消息连接在线但群目录接口明确返回需重新认证时，页面单独提示重新登录； 消息连接状态不因此伪装为离线，也不能据此宣称成员查询或结账可用。

business_auth 单独报告业务凭证状态及实际设备类别，不含设备编号、凭证或 密钥。credential_present 只代表持有凭证，不代表已验证所有接口可用。 任一业务接口收到明确 401 后，立即将其标记为 expired，后续业务请求 在本地拒绝；即使群目录曾读取成功，页面也会提示业务登录失效，不再只显示 绿色“账号已在线”。暂时的网络错误及 1400 不冒充设备冲突。

手机与机器人登录

程序运行在服务器上不等于使用桌面端登录。官方设备分类中 1 是桌面、 3 是安卓；安卓 3.7.3 登录同时绑定安卓设备类型、客户端标识及签名版本， 可能与手机登录相互影响，不能据此宣称官方禁止手机与桌面端同时在线。

新增桌面 2.8.3 兼容分支，对齐发布包中的桌面签名版本、设备类型和客户端 标识，并使用当前 get-nim-token 路径及持久化消息设备编号。桌面登录仍需 验证服务器返回的绑定令牌；要求安全验证时仍须完成，不能伪造或跳过。 不会仅把安卓凭证的设备类型改成桌面，也不伪造安卓安装包校验字段。

IM 连接会保留当前令牌接口返回的静态、动态或回调认证类型，并将其传给消息 服务；回调令牌不能当作静态令牌使用。未知类型直接拒绝，不尝试降级为静态 令牌，也不把令牌或认证响应写入诊断日志。旧接口未返回类型时保留静态兼容。

由部署管理员选择新登录协议后，通过后台重新登录并保存才会使用新分支。 已保存的安卓、旧版和桌面会话均按各自协议恢复；更改部署或重启不会转换 已有凭证、重置设备编号、自动重新登录或清除账本。桌面分支的离线回归通过 不等于手机共存已验收，仍须取得重新登录及手机再次登录后的真实读取证据。

连接在线、群列表可读、完整成员可读及业务已启用是独立检查项。 成员查询失败不再统一误报“开放服务未连接”：后台区分身份冲突、名单不完整、 响应超限、平台拒绝、安全验证和限流，技术诊断使用 AstrBot 原生日志并脱敏。 不使用部分成员资料授权或结账，不通过自动重试掩盖读取错误。

运行状态的 receive_health 分开记录未处理的非聊天推送、无效数据包、 消息解码失败及暂不支持的消息格式；decode_reasons 只包含固定失败阶段， 不记录消息正文、密文、密钥或原始平台响应。非聊天推送不再增加 unsupported_pushes，但仍保留独立计数，不声称已经支持对应通知。 decoded_messages 记录实际通过解析的消息数，decode_shapes 仅汇总有界的 协议字段编号和类型，不包含字段值，便于区分尚未兼容的封装。 接入页只对实际解码失败显示独立提醒，不以历史总数判断当前登录失败。 累计计数属于本次运行，旧的“未支持推送”总数无法事后还原为这些分类。

接收同时兼容旧消息封装及官方 3.7.3 的 MessagePacket 第1版： 先验证独立认证数据，再验证内层消息；不能用封装中的账号资料授予权限。 零压缩标记的消息仍须通过认证和路由核对，不将其直接当作可信明文。 未知封装版本、嵌套封装及任一认证失败均拒绝，普通消息的1MiB上限不变。 同时兼容官方编码器允许的整数变长／定长编码；同一字段的矛盾编码拒绝。 实测仍有缺少认证字段的封装，这部分继续拒绝，不据此声称所有消息已兼容； 它们不会进入群管、AI或结账，需取得可信格式依据后再增加支持。
