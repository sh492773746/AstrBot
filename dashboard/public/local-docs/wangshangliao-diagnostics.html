字段说明

字段 含义
instance 机器人实例标识，不是用户昵称
stage / outcome 处理阶段及真实返回状态
correlation 消息或任务标识的 SHA-256 前 16 位；同一原始消息可关联路由、审核和处罚

duration_ms 调用点测量的阶段耗时；未测量为 -，不是所有链路的端到端耗时

后台名片任务以任务 ID 为关联值；新确认消息与预览消息有不同的消息关联值。 因此 correlation 不是跨全部会话、全部发送分片的全局调用链 ID。

收件兼容分类与“没有积压但漏读”（2026-10-25）

pending=0只表示当前没有待处理消息，不代表所有上游封包都已识别。 官方3.7.3同时支持带认证标签及标记为0的明文封包；接入器不能把后者 直接当成已验证的群管命令。/api/platform/stats的receive_health现区分：

  • decoded_messages：通过应用层认证及路由校验的消息。
  • plaintext_notices：由已知群的真实传输路由归档、格式为7／8的明文群通知／公告。 收件状态为plaintext_notice，只保留未验证的格式号及原因，不保存正文、昵称或声称的身份。
  • unverified_messages：其他可解析的无认证明文，状态为unverified_message， 以error=message_unverified告警，不进入关键词、AI、排行榜、处罚或财务处理。
  • unverified_formats：有界格式计数，未知大格式号统一计入other，不能作为权限依据。
  • decode_failures：损坏封包、认证失败等真正解码失败；不与上述两类重复累计。

已认证但不支持的群消息也记录有界format和reason，不再保存无解释的空对象。 已认证7／8格式仅归档为application_notice。这些应用层提示均不等于可信入群事件， 不会替代原生成员通知、触发黑名单重入处罚或变更名单／财务。 所有分类先提交收件记录再ACK，重复投递不重复建档，提交失败不ACK； 计数按接收尝试累计，不等于独立消息条数。未知封包不打印／保存正文或密文， 不自动重试、补读或重置成pending。旧记录没有原始正文时，不能据时间相关性补造分类。

状态不能混淆

  • preview：仅生成预览，未保存或执行。
  • saved：配置已保存，不代表活动已开始；抽奖启动以 started 及活动状态为准。
  • schedule_confirmation_required：仍需完成定时规则的确认。
  • accepted：上游受理，不是最终状态核验完成。
  • verified：已核验；名片和其他异步操作应以任务查询结果为准。
  • unknown、not_confirmed、needs_review：保留现场并查询结果，不要重发管理操作。
  • command_reply / send_returned：回复调用已返回，不保证实际送达；看 reply_result 和接入器发送账本。

正常路由与预期权限拒绝通常记为 INFO；原生receive/received、 process/started、process/completed和recall/observed记为DEBUG， INFO日志缺少这些逐条记录不证明没有入站。异常、失败回退、未知回执通常记为 WARNING。 接入器原有需要人工介入的终止类错误仍为 ERROR。 重复后台错误在 60 秒内聚合，缓存最多保留 512 个失败窗口；窗口淘汰或后续 失败触发过期清理时补记被抑制的数量。没有后续事件或进程退出时，不保证输出 最终汇总；日志不是精确的持久计费或处罚计数账本。管理工具返回、逐次处罚回执 和登录操作结果不聚合，避免不同登录步骤与平台返回码被合并。

隐私边界

这些结构化日志不记录聊天正文、AI 提示词、模型回复全文、工具参数全文、 确认口令、成员名片、账号密码、Token 或 Cookie；自由异常文本不直接写入。 哈希用于排障关联，不是匿名化证明，不应公开提供可关联用户的完整日志。 AstrBot 其他模块、第三方插件或 DEBUG/trace 日志可能另有正文记录， 不能据此认为整个日志文件均已脱敏。对外提交前仍需筛选和人工检查。

日志只负责观察，不会改变管理员身份、群授权、模型选择、处罚次数或开启自动踢群。 2026-10-20本轮仅静态读取及内存mock核验，没有发起网络请求、运行服务检查脚本或写库， 不代替真实用户的四种身份会话验收。
