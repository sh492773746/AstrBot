## 名单、阈值与验收边界

广告审核开启时，单条消息超过7行（8行及以上）按广告处理，沿用原警告／禁言循环。
7行及以内不因行数命中；其他广告关键词及推广组合仍独立识别。
只统计实际换行，CRLF计一次，空行与末尾空行计入；屏幕自动折行和字面`\n`不计。
支持LF、CR、CRLF及Unicode行／段分隔符；管理员、机器人和有效白名单保护不变。
这是独立格式规则，不以联系方式、关键词或OCR为前提，引用举报与普通多行聊天也可能命中。

## 代码结构

现金返现仅由已有相应后台权限者在活动与财务 → 邀请记账／结账维护，使用原账本、
记录版本、资格、风控与付款确认。群管理与旧聊天财务角色都不授予全局后台登录。
群内`我的邀请`只查活动邀请，不显示个人现金或付款资料；不把旧私信查询移到公开群。
只登记外部实际付款，不自动转账；关闭新增返现不清除旧欠账，退役不删除历史财务。
`command_capabilities.py`声明保留群命令，`syntax.py`与`commands.py`维护识别与执行。
私信专属业务代码、旧菜单、客服与好友模块已物理删除，不保留隐藏私信执行入口；
不删除或迁移群图文、群AI、活动及财务账本，也不因删码清理历史业务数据。
规则、图文、活动、统计及财务继续使用原存储，不为退役迁移或重建业务库。

底层登录、传输、真实身份和平台动作在
`astrbot/core/platform/sources/wangshangliao/`，不在插件中重复实现。
旧独立公共进程启动器只保留拒绝提示；财务Socket继续使用，不应一并删除。
测试脚本只可显式运行，不注册到生产聊天、AI或定时任务。
