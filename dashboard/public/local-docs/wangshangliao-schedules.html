固定命令流程

每条为单独新消息：

管理 群列表
管理 选择群 1
管理 定时禁言 23:00 08:00
管理 确认定时 <预览码>
管理 定时状态

时间严格 HH:MM 且不相等。预览包含目标、时区与下次动作；确认码600秒有效、 一次使用，绑定账号、管理员、对话、群和版本；确认前重新鉴权。保存/恢复仅安排下一个 严格未来边界，不立即改变群状态。例如凌晨保存此例，下次动作是08:00解禁。

命令 效果
定时状态 状态、下一动作、最近回执和故障原因
暂停定时 停止未来调度，不解禁当前群
恢复定时 新预览，经新确认后从未来边界恢复
删除定时 删除未来计划，保留审计，不解禁

聊天菜单为5→2设置、5→3查状态、5→4暂停、5→5恢复、 5→6删除、5→7确认已有申请。菜单数字绑定本人账号及对话，不是权限凭据； 群内菜单及固定命令可用，同一发送者预览后才能确认，旁人回复数字不能接管。

插件页“运行与日志 → 定时管理”（旧入口“定时管理”）可看状态、执行和变更记录，并按当前版本暂停； 不直接创建/修改/恢复，后台权限不替代聊天管理员身份。旧版本暂停返回冲突须刷新。 页面仍有“恢复或改时段需私聊”的旧提示，公共合并模式源码实际也支持本群授权管理在群内确认。

运行、安全停止与审计

schedules.py 每五秒检查，插件卸载停止 worker。schedule_store.py 将账号、群、 创建者、原私聊路由、时区、版本和下一边界保存在 schedules.sqlite3； confirmations 一次确认，executions 执行声明/结果，rule_audit 记录变更。 执行意图先提交 SQLite，幂等 ID 绑定账号/群/版本/计划时间/动作。

公共合并模式已停用手动禁言、全员禁言及解除全员禁言聊天命令； 旧命令只提示使用官方App，不提交动作，也不暂停计划。单成员解禁／解除禁言仍可用， 不会暂停每日全员计划。自动处罚和本页定时功能保留。 内部兼容的人工全员动作执行器仍会先暂停该群计划，并与调度共用 adapter 群锁； 这不是公共聊天入口仍可调用这些旧命令的承诺。 其他管理员在旺商聊客户端直接改状态时不能可靠推断其意图，人工接管前先暂停。 暂停/删除无法撤回已提交上游的请求，也不自动恢复群状态。

到期执行时发现创建者撤权、换账号、断线、群停用、授权取消、错过边界、 同版本未完成声明、调度延迟超过30秒或未知结果会暂停待核查；不是所有变化发生时都即时暂停。 重启不补发错过动作，尚未到期且无未完成声明的计划可保留。 执行前及目录查询后均复核授权，accepted 不冒充 verified，unknown 不重试。 核对真实群状态后，重新预览与确认恢复；不能删账本“修复”。

原生角色变化有独立例外：native_permission(False)把活动计划转为role_paused （native_permission_lost），保留时间配置、增加版本并删除旧确认； 之后确认机器人恢复原生管理员角色且原创建者仍具动作授权时，可自动从严格未来边界恢复， 不要求再发恢复定时，也不补做角色缺失期间的动作。人工paused不走此自动恢复分支。

当前限制须单独区分：

  • 创建者同时列在有效路由admins_id中时，tick.check跳过当前在群名单复核； 公共业务授权仍检查，但不能宣称所有创建者都已重新确认在群。
  • 前端未翻译role_paused，暂停原因也直接展示内部代码；它不等于已持久化的人工暂停。
  • 后台暂停接口仅对active保存paused，对role_paused可返回paused=true却不修改状态， 且界面此时不显示暂停按钮；不能把该返回值当成已阻止角色恢复后的自动调度。 需修复并覆盖“角色暂停 → 人工暂停 → 恢复原生权限”的完整回归。
