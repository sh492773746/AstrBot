结账流程

默认显示待结账记录，按邀请人真实账号分组；支持群筛选、姓名搜索、展开明细、分页、 已结账和已作废查询。2026-10-12 起，旧“每100笔分页”改为每页最多5位邀请人； 同一邀请人不会再被拆成多个独立分组。分组标题显示当前群、状态、姓名及时间筛选范围内 该邀请人的总人数和总金额；成员超过100人时，只在该分组内分页，标题总额保持不变。 未归属记录同样在唯一分组内分页。昵称相同的不同账号不合并，历史改名不拆分账号。 “选择本页可结账记录”只选择该邀请人当前成员页，每次提交仍最多100笔，不自动跨页结账。 翻页和筛选会清空旧勾选；刷新后页码超出范围时自动回到有效页。已结账、核验中及作废状态 均使用相同分页规则，页面汇总及分组、明细读取同一数据库快照。 同一浏览器标签页刷新时保留上次选中的群；若该群已不在授权列表，才回到当前可见群。 重新打开默认仍查待结账，不因进入群设置或发生保存冲突而把账目标成已结账。 重名通过真实账号辅助标识区分，不按昵称匹配身份。 分组标题明确标注“邀请人”；每条明细标注“被邀请人”，并重复列出其对应邀请人姓名和真实账号， 不依赖分组位置猜测谁拉了谁。具备现金资格但缺少可靠归属的记录单列“未归属”， 不计入待结账金额或可付款选择；永久基线、自然进群及禁止资格的记录仍排除。 已付款历史保持可查，收款人仍明确标注为历史登记收款人。 付款确认框标明“收款邀请人”及真实账号，被邀请人名单不是收款人名单。 时间统一北京时间；明细中的“首次核验入群”是完整名单首次确认时间，不冒充未知的平台精确入群时间。

提交前服务端重新获取完整名单。名单不完整、归属不可靠、已经退群、记录版本变化时， 整批拒绝，返回原因。只修改确认时选中的记录，新产生的邀请仍待结账。 网络重试使用同一幂等请求标识，成功登记不会重复执行。

群内查询

已配置现金返现的群中，“我的邀请”和“邀请奖励”优先读取该群独立现金账本， 显示本人返现邀请记录、在群／退群人数、当前每人金额、待结账和已结账金额及群内联系人。 “我拉了谁”显示本人返现邀请的名称、在群及结账状态，最多20条。 使用消息发送者真实 UID 查询，不接受代查他人的参数，不公开其他人的余额或登录身份。 未启用旧积分统计也可查询现金账；现金返现暂停后仍可查历史，显示“返现已暂停”。 积分存在时单独列出，不折算现金，不用历史邀请人数乘当前单价。 从未配置现金返现的群继续使用原邀请积分查询。查询仅只读，不触发付款或追溯补账。

编辑群设置期间暂停实时刷新；其他管理员或浏览器标签页先保存时， 服务端拒绝旧版本覆盖，页面载入最新资料，核对后再次保存，不自动重试写入。 重新进入群设置或点击刷新时重新读取设置版本；读取期间表单不可编辑， 避免已刷新群列表但仍提交旧表单版本。成功保存后账本切换到刚保存的目标群。 报错中的请求编号可以在“操作日志”精确查询；保存冲突不会修改现金账单。 修改联系方式不改变网页登录权限；历史成员联系人表仅用于兼容旧记录。

人工分类与三小时核验

新记录先进入核验中，从完整名单首次确认被邀请人在群起保存3小时期限， 显示剩余时间。期限到达后，采集器重新核验完整名单、邀请归属、在群状态及单价， 全部通过才转入待结账。退群或重复入群作废，不重建奖励资格。 期限持久化，短暂重启不丢失；监测间隔超过120秒时重新观察3小时并记审计， 不把无法确认的离线时段当作连续在群证明。到期转换依赖成功采集，不保证秒级执行。 普通登记不能绕过新记录核验，前端倒计时不授予结账权限。 管理员异常补记仅记录已经实际发生的外部付款，不代表核验通过，规则见下节。

升级只为现有群的新邀请启用此规则；既有记录保留原金额、状态、付款、资格和版本， 不把旧账退回核验中，不恢复已退群记录。新创建或保存的群固定采用3小时核验。

切价确认、异常补记与旧债

POST /api/price-preview 返回服务端计算的原价、目标价、记录和价格规则版本、 当前群规则版本及摘要。operation=reprice 必须携带完整 price_confirmation； 提交事务重新计算并核对全部确认内容，幂等摘要也包含这些字段。 旧页面缺少确认数据会被拒绝，应刷新后重新预览，不自动补齐或重试。

仅财务管理员可做异常补记，必须填写原因并勾选“确认已经实际付款” （actual_payment_confirmed=true）。这可以补记尚未满三小时、未发言或已经退群的 实际付款，但不能绕过收款身份、已确认邀请归属、合法价格、风控或重复付款检查。 原资格证据和异常原因保留，页面及日志区分正常登记与异常补记，不恢复退群作废资格。 撤回异常补记只撤销登记，不撤销外部转账，也不使作废奖励重新生效。

新邀请采集基线与既有欠账的证据周期分开保存；关闭再开启不使合法旧债失去证据。 旧数据只补充能可靠证明的周期元数据，不猜测归属或重算金额。 首次升级会一次性清空来源扫描游标与扫描时间，以重新采集完整成员事件； 这是采集元数据迁移，不修改旧金额、归属、付款或结账状态。 最新可信退出／自然重入不能被旧邀请覆盖；单条缺少邀请人的来源单独留存审计， 不影响其他有效记录。历史疑点仅输出只读核对清单，不批量修账、冻结或追扣； 新付款发现证据矛盾时拒绝提交，不自动改写原账。

首次新邀请、普通账号、可靠归属及完整名单 生成独立现金记录，符合核验条件后可登记
自邀、已接入机器人、待审核邀请 不可普通结账
具备现金资格但缺少可靠邀请人归属 单列“未归属”，不计入待结账金额、不允许直接结账
未结账前退群 作废；重新拉入也不恢复
已结账后退群 保留原付款，不追扣，只更新成员状态
换机器人、邀请人、昵称、重复事件 不重建现金资格
修改单价 仅影响新邀请，旧记录金额不变
归属冲突、身份映射冲突 保留原记录并阻止普通结账
已实际付款，但登记时发现退群等异常 管理员填写原因，通过“异常付款”补记实际付款
撤回结账登记 结账员仅可撤回本人登记；管理员可撤回全部，必须填原因

在“结账状态”选择“已结账”，点击记录的“撤回结账”，填写原因并“确认撤回”。 也可选择同一邀请人的多条本人登记记录，批量撤回。取消确认不会修改账目。 撤回成功后页面切回“待结账”，保留群、姓名和时间范围筛选； 已满足核验截止时间且价格已配置的在群记录转回待结账，未完成的继续核验； 曾退群或当前不在群的记录改为已作废，不恢复返现资格。 撤回不修改金额、普通成员／代理商分类或邀请归属，也不会自动退回实际支付的款项。 原付款、撤回、操作者、时间、原因和状态前后值均保留在“操作日志”，不删除原付款历史。 原“更正”／“更正登记”入口现统一称为“撤回结账”，日志称为“撤回结账登记”； 后台继续使用 operation=correct，旧审计与请求幂等记录保持兼容。 异常登记不是转账操作，也不能替代线下核对付款对象。

返现风控

同一邀请人在五分钟内邀请至少10位不同成员，且至少90%的入群名称长度相同， 会生成预警；首次群内提醒的发送／受理状态单独保留，不能把入账当作送达。 后续独立命中冻结该邀请人在本群的未结返现，普通及异常登记不能绕过； 不踢群、不禁言、不改已付款。来源、群、账号及原入群周期仍须核验， 未知名称不能自动当作相同长度命中。网页管理员或本群 finance_admin 可填写依据复核解除，不代表此前资格自动通过；网页切群和嵌入模式的已知缺口见开头。

多群设置

机器人勾选多个群后，需要在结账页逐群保存金额、联系人和开关，没有批量套用设置。 联系方式无需属于群成员；仅关闭现有返现且其他设置不变时， 不要求重新取得名单。网页登录结账员仍可处理全部已配置且勾选的群。 单价、付款、退群及启用基线按群独立；同一真实 UID 首次进入两个不同群可以分别计奖， 这不是跨所有群仅奖励一次。取消机器人勾选会跳过该群后台采集并禁止结账操作， 不删除历史；恢复勾选不补齐平台未提供的离线历史。 各群独立采集，健康间隔10秒，共用最多3个后台采集名额；失败群独立退避， 不会阻止其他群继续尝试。付款登记仍单独重新核验目标群。

采集复用接入器的完整成员名单、真实 UID/NIM 映射、原生邀请通知及可见业务邀请记录。 现金去重键为固定旺商聊平台内的“群业务 ID + 被邀请人真实 UID”，不含机器人实例或邀请人。 原生通知保留平台时间；只有接收时间、没有可靠事件时间的旧通知不直接放行付款。 业务邀请记录必须已同意、身份一致、邀请时间不早于启用边界；待审核不计奖。

采集周期还受平台请求耗时影响。重复原生入群通知也会保守识别重拉； 平台未提供、机器人离线期间未收到且从未记录过的历史，不能声称已覆盖。 若退群再加入发生在两次名单采集之间，且平台没有提供新的可靠事件，本地无法还原这段历史。 不能用用户聊天自述或昵称推断邀请归属。证据不足的记录应保持待核对。

部署脚本使用服务器已有受保护 CF 凭据，只创建结账页独立 Access 应用及域名， 保留现有 Tunnel 路由和后台策略。prepare/publish 可重跑，不覆盖未知同名应用或 DNS。 service_mode 支持 embedded 与 standalone，配置缺省为 embedded。 嵌入模式由插件监听 127.0.0.1:6186；独立模式由单独网页进程监听该回环端口， 插件只运行采集及受保护的 rpc/cashier.sock，没有第二个机器人登录。 独立网页直接读取同一账本，涉及平台核验的写入经允许列表Unix RPC回到插件， 原Access JWT重新验证；角色不由浏览器传入。插件不可用时保留获准历史查询， 写请求拒绝，不自动重试或另建账本。此处说明可用部署模式，不宣称本次变更运行配置。 不开放通用 AstrBot API；所有写请求要求固定同源 Origin 和 JSON。 响应禁止缓存、禁止框架嵌入；未登录也无法读取静态页面。

独立 SQLite 账本：data/plugin_data/wangshangliao_cashback/cashback.sqlite3。 启用 WAL、事务和唯一约束；付款登记与审计及幂等结果一起提交。 已有积分、活动库仅供只读历史核验，不转换、不清零、不写回。 备份脚本使用 SQLite backup API，避免运行中只拷贝主文件遗漏 WAL。 恢复时先停服务，恢复整个一致性快照，不能只恢复部分付款表。

故障时可在群设置关闭返现，保留全部账本；同一机器人、单价、结账员不变的关闭操作 不要求机器人在线。彻底停入口可移走 access.json 后重启，账本不删除，群管和抽奖不受影响。 服务日志只记录群标识与安全错误码，不输出 JWT、支付信息或邀请原始载荷。 结账页使用 SSE 接收账本变化通知，正常情况下不必等待下一轮整页刷新； 连接断开会自动重连，定时刷新仍作为兜底。SSE 只推送变化信号，不推送账目或身份数据。 各群按独立周期采集，正常每轮后等待10秒，后台最多3群并发； 失败群独立按20、40、60秒退避，不阻塞其他健康群的下一轮。 平台名单核验仍可能耗时；并发上限不是大规模群数下的时延保证。 独立结账进程设CPU上限50%、内存软限256MiB／硬限384MiB、任务上限128； 共享AstrBot采集仍不具备跨平台CPU、内存或模型配额硬隔离。 选择记录和付款确认期间延后刷新， 结束操作后再更新，避免新邀请改变当前付款批次。推送每秒复核本地身份和群权限， 每60秒重连重新验证 Access，登录过期或撤权后停止推送。 仅扫描时间更新不触发SSE业务刷新；已绑定身份仍每秒查撤权，但不反复取得SQLite写锁。 核验中明细显示预计时间，并区分在群时间、缺名称、缺代理价和归属待核对。
